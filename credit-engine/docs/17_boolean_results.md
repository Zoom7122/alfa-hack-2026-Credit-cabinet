# Логические значения в результатах и событиях

EconomicCriterion.value поддерживает число, boolean и null. Ключи критерия остаются прежними: id, value, points, max_points. Описание обновлено в основном OpenAPI; изменение применяется одинаково к ответу МС1, запросам МС2 и AdminEvent.

```json
{"id":"EXAMPLE_BOOLEAN","value":false,"points":0,"max_points":0}
```

Это пример представления, не новая действующая модель/вес. false — известный отрицательный ответ. null — неизвестное значение; оно не превращается в false/0. Бизнес-обязательность факта по-прежнему определяется моделью: неизвестный обязательный факт приводит к NEED_INFO до банковской операции.

## Go-представление

Для совместимости числовые коэффициенты сохраняют прежнее поле Value *float64. Логические значения представлены BooleanValue *bool. Оба отсутствуют у неизвестного значения; одновременно задавать оба нельзя. MarshalJSON/UnmarshalJSON используют один wire-ключ value, поэтому BooleanValue не появляется отдельным полем JSON. Старые числовые результаты и порядок ключей сохраняются.

Строки "true"/"false"/"1", объекты, массивы и неконечные числа не являются допустимыми значениями. Неудачный разбор не изменяет уже заполненный критерий. ValidateValue проверяет взаимоисключение и конечность до операции банка; копирование и сериализация тоже отклоняют неоднозначный объект.

[scoring.ToAssessment](../internal/scoring/result.go) переводит типизированный результат общего расчёта в существующий процесс МС1: числовые показатели сохраняют double-представление, boolean остаётся boolean, неизвестный показатель — null. Анкетные ответы сохраняют своё текстовое представление. Полное подключение нового конвейера выполняется отдельно после проверки совместимости.

## Передача и повторы

MS1 BankClient → HTTP МС2 → банковское копирование/проверки → AdminClient → AdminEvent сохраняют тип value. Это относится к LOAN_ISSUED, BORROWER_REVIEW и BANK_REVIEW. Идентичный повтор сохраняет существующую выдачу/событие; изменение false/true/null при том же application_id является изменением payload и приводит к конфликту.

Поддержка логического типа не меняет банковские формулы, баллы v2 или правила начисления. Новые веса задаются в проверенном определении модели.
