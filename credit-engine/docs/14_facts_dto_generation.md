# Именованные DTO дополнительных фактов

[GenerateFactsDTOs](../internal/modelgen/facts.go) получает проверенные определения моделей и возвращает Go-файлы DTO и доступа к значениям. Генерация не пишет файлы, не публикует модель и не включает новый запрос в МС1. Базовые ip-v2/legal-v2 не имеют источников SUPPLIER и не порождают DTO поставщика.

## Генерируемый контракт

Для каждой использующей поставщика версии создаются:

- отдельный тип блока additional_facts с именованными полями;
- тип ответа, включающий общую метаинформацию и этот блок;
- строгий разбор JSON и функция Decode…Response с ожидаемым запросом и датой оценки;
- функция доступа к именованным полям, переводящая их во внутренние типизированные значения общего расчёта.

Имена полей задаются json_name/go_name из модели и проверяются общим валидатором. BOOLEAN получает `*bool`, целое NUMBER — `*int64`, дробное NUMBER — `*float64`. Указатель отличает неизвестность от 0/false; omitempty не используется. Каждый объявленный ключ требуется в JSON даже при необязательности бизнес-факта. Отключённые параметры в схему не входят.

Типы разных версий ИП/ЮЛ сосуществуют. Повтор версии модели, коллизия Go-имён и несовместимые поля/типы/единицы/домены под прежним facts_schema_version блокируют генерацию. Порядок входного списка моделей не меняет результат. Изменение только бизнес-обязательности не меняет transport-nullability: бизнес-проверку выполняет скоринг. Объявление новой структуры данных требует новой версии схемы.

Функции доступа читают конкретные Go-поля без reflection. Универсальная map не заменяет DTO ответа: временные raw-объекты нужны только разбору JSON, а внутренняя карта rules.Value используется общим исполнителем по именам источников.

## Строгий разбор

Общие типы запроса/метаданных/ожиданий определены в [contracts/scoring_facts.go](../contracts/scoring_facts.go). Перед разбором ответа вызывающая сторона передаёт ScoringFactsExpectation с исходным запросом и ненулевой датой оценки. INN в запросе сохраняется явно, включая null.

Порядок Decode…Response:

1. Ограниченное чтение: максимум 1 MiB, глубина 64, корректный UTF-8, один JSON-документ; дубли ключей запрещены, включая экранированные формы одного имени.
2. Точная оболочка: обязательные ненулевые ключи, регистр имён, типы, отсутствие лишних полей.
3. Сопоставление идентификаторов, типа заёмщика, модели и схемы с исходным запросом и выбранным сгенерированным типом.
4. Календарная дата YYYY-MM-DD, не позднее явно заданной даты оценки в UTC.
5. Именованный блок: все ключи присутствуют, null разрешён для бизнес-значений, известные значения проверены по типу и домену.

Обычный json.Unmarshal в сгенерированный тип также проверяет точные ключи/типы/домены и фиксированную версию; проверка повторного запроса/будущей даты требует Decode…Response с ожиданием. Неудачное UnmarshalJSON не изменяет уже заполненный DTO.

Целые числа разбираются точно, включая значения выше 2^53 и границы int64. Числовые записи 1.0/1e1 допустимы для целого типа, если математическое значение целое и помещается в int64; дроби/переполнение отклоняются. Для float64 сохраняется его обычное конечное представление. На числовой токен действуют ограничения 256 байт и модуль экспоненты 512. Границы int64 сравниваются точно; float64 — в представлении этого типа. Строки с числами/boolean не преобразуются автоматически.

## Ошибки и неизвестность

ScoringFactsError возвращает код и пути схемы без содержимого ответа. INVALID_FACTS_RESPONSE означает неверную форму/тип/дату/домен; FACTS_ID_MISMATCH — чужие идентификаторы/тип; FACTS_VERSION_MISMATCH — модель/схема. Причина ошибки чтения сохраняется для распознавания тайм-аута внешним REST-адаптером.

Корректный null не является ошибкой протокола. Генерируемый доступ к значениям сохраняет Unknown; обязательный факт затем приводит к NEED_INFO с путём additional_facts.<имя>, если более приоритетный стоп не подтверждён. Сетевые ошибки, HTTP-статусы и доставка запросов относятся к REST-клиенту, описанному в [контракте поставщика](09_scoring_facts_contract.md).

Компилируемые проверочные DTO находятся только в файлах *_test.go и имеют префикс Fixture. Они не включены в рабочую сборку и не регистрируют демонстрационные версии как поддерживаемые.
