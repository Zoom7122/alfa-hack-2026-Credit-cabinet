## Команды

В Linux-контейнере с исходниками и Go:

```sh
go test -count=1 ./...
go vet ./...
go test -race -count=1 ./internal/...
go test -race -tags=integration -count=1 ./internal/adminstore
go run ./cmd/modelgen check
docker build -t credit-engine:acceptance .
```

Интеграционный прогон требует CREDIT_ENGINE_TEST_ISOLATED=1 и CREDIT_ENGINE_TEST_DSN, указывающий только на отдельную БД credit_engine_admin_test. Он создаёт и удаляет дочерние БД, не рабочую БД приложения. Docker build выполняется снаружи Go-контейнера.

Чистые JavaScript-проверки: internal/adminui/testdata/numbers_test.mjs и model_edit_test.mjs. Браузерные сценарии: ui_workflow.mjs и admin_acceptance.mjs. Они запускаются только с CREDIT_ENGINE_UI_TEST=1, PLAYWRIGHT_MODULE и CREDIT_ENGINE_UI_OUTPUT против специально поднятого локального порта 18084. Пакет/образ Playwright должны иметь одинаковую версию; рабочие зависимости приложения Node не требуют.

Расширенный браузерный сценарий добавляет boolean в анкету и число в дополнительные показатели, перераспределяет баллы, меняет стоп/класс, сохраняет ревизию, проверяет false/null, выполняет сравнение, проверяет отказ выпуска при неверных весах, получает документы/ZIP/SHA, сохраняет повторяемое событие и проверяет фильтр/карточку/рабочий каталог. Результат и артефакты сохраняются в отдельном каталоге проверки.
