# Сообщения и работающие версии

## События МС2

Список «Сообщения» фильтруется по типу события, типу/ID заёмщика, ID заявки, версии модели и включительному периоду RFC3339. Пагинация сохраняет фильтры. ID заёмщика сопоставляется точно, по сохранённому payload. Условия формируются параметризованным SQL; новые колонки БД не нужны.

Карточка показывает идентификаторы, время возникновения/фиксации, SHA-256, запрошенные/выбранные условия, результаты подбора, анкету и дополнительные критерии, причины и банковские проверки. Boolean false, ноль и неизвестный null выводятся различно. Событие нельзя изменить или принять по нему решение в этом MVP.

## Запущенные версии

МС1 предоставляет GET /api/v1/models: format_version=1, models с ID/версией/типом, версиями схем и SHA-256 фактического встроенного каталога. Метод не читает админскую БД или файлы модели и не меняет рабочую оценку. Контракт: contracts/scoring_metadata.openapi.json. Метод предназначен для внутренней сети стека.

Админка получает сведения только через защищённый GET /api/admin/v1/runtime/models. Серверный адрес задаётся ADMIN_SCORING_URL, тайм-аут — ADMIN_SCORING_TIMEOUT (по умолчанию 2s, меньше общего ADMIN_REQUEST_TIMEOUT). При отсутствии адреса доступен просмотр подготовленных релизов, а сведения МС1 имеют отдельное состояние «не настроено». Недоступность, тайм-аут и неверный ответ не заменяются данными подготовленного комплекта.

Клиент делает один ограниченный запрос без повторов и перехода по redirect. Ответ проверяется по именам, типам, обязательности, версиям и контрольным суммам. UI показывает время успешного запроса и возможность обновить. Подготовленные архивы и полученные от МС1 версии/SHA отображаются отдельно.
