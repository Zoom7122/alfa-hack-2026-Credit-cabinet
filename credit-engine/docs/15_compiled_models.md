# Статические модели и каталог сборки

[GenerateModels](../internal/modelgen/models.go) формирует Go-описания проверенных моделей, необходимые DTO/привязки фактов и каталог версий. Работающий МС1 не загружает правила из JSON/Excel/БД. Изменение модели начинает действовать после генерации, проверки, сборки и развёртывания.

## Состав

| Артефакт | Содержание |
|---|---|
| `internal/modelbindings/model_<идентификатор>_generated.go` | Конструктор model.ModelDefinition из Go-значений: параметры/источники, обязательность, условия, баллы, особые случаи, проверки, стопы, ручные основания и классы. |
| `internal/modelbindings/catalog_generated.go` | Поддерживаемые версии и метаданные, привязки к конструкторам и типизированным декодерам фактов. |
| DTO и доступ к полям | Создаются только для моделей с активным SUPPLIER; описаны в генерации DTO. |

Текущая исходная сборка каталога содержит ip-v2 и legal-v2. Демонстрационные версии из тестов не становятся рабочими записями. Имена файлов определяются стабильным идентификатором версии; входной порядок моделей не меняет результат. Генератор возвращает байты и относительные пути без записи файлов.

Числовые Literal/Bound сохраняют десятичный токен, именованные Go-типы — тип/единицу источника. Непустые указатели на 0/false/пустую строку не теряются. Порядок массивов и различие []/nil сохраняются; даже отрицательный ноль в допустимых дробных баллах сохраняется при конструировании. Строки определений экранируются как Go-литералы, произвольный код из модели не исполняется.

## Каталог

[modelbindings.NewDefault](../internal/modelbindings/catalog_generated.go) создаёт [неизменяемый каталог](../internal/modelbindings/catalog.go). При создании проверяются метаданные, контрольные суммы, уникальность версий, согласованность схем фактов и наличие нужного декодера; каждый исполнитель компилирует и проверяет встроенное определение. Несогласованный комплект завершает инициализацию ошибкой.

- Lookup требует точную версию и соответствующий тип заёмщика. Неизвестная версия не заменяется другой.
- LegacyVersion сохраняет постоянное соответствие запросов без версии: ИП → ip-v2, ЮЛ → legal-v2. Это не выбор «последней» модели.
- List/Metadata возвращают копии метаданных; Engine возвращает неизменяемый исполнитель для конкурентных оценок.
- CanonicalDefinition/Definition возвращают независимую копию описания для инструментов и админки. Внутреннее преобразование этой копии не читает модель из внешнего источника.
- DecodeFacts связан с конкретными сгенерированными типами ответа и доступа к полям. У v2 без поставщика такой привязки нет.

Список поддерживаемых версий фиксируется исходниками сборки. Сохранение черновика/подготовка релиза не меняют уже созданный каталог работающего процесса.

## Контрольные суммы

DefinitionSHA256 вычисляется по каноническому model.Marshal: включает версии, все правила, массивы и числовые токены. Он не зависит от платформенных окончаний строк Go-файла. Изменение правила меняет Go-описание и контрольную сумму в каталоге.

FactsSchemaSHA256 вычисляется общей функцией [model.FactsSchemaSHA256](../internal/model/facts_schema.go) по активным JSON-именам, типам, единицам, integer и границам доменов. Порядок ключей, ID параметра, Go-имя и бизнес-обязательность не меняют форму nullable-transport. Одинаковый facts_schema_version не может обозначать несовместимые формы. У моделей без поставщика эта сумма пустая.

Побайтовые суммы артефактов комплекта релиза учитываются отдельно от суммы самой модели. Перед переключением полного процесса требуется самостоятельная проверка эквивалентности сгенерированной v2 с действующими эталонами.
