# Контейнерная поставка

Команды выполняются из credit-engine в Linux с Docker. Один многоэтапный образ содержит /scoring-service, /bank-state-service, /admin-service, /admin-migrate, /modelgen и вспомогательный /admin-password. Встроены интерфейс и административные миграции; конфигурация находится в /app/config. Сервисы запускаются отдельными процессами/контейнерами от непривилегированного пользователя. Shell/curl внутри конечного образа нет.

## Сборка и запуск

1. Соберите образ: docker build -t credit-engine:local .
2. Подготовьте отдельную PostgreSQL-БД либо роль с правами создания собственной схемы credit_engine_admin в БД общего стека. Не используйте рабочую БД для тестов.
3. Заполните локальный env-файл по config/admin.env.example. Передайте имя существующей сети, адрес Б, БД, логин, bcrypt-хеш и общий секрет МС2/МС3. Файл с секретами не включайте в Git.
4. Примените миграции отдельно, затем запустите три сервиса:

```sh
docker compose --env-file .env.admin -f compose.credit-engine.yaml run --rm admin-migrate up
docker compose --env-file .env.admin -f compose.credit-engine.yaml up -d
```

Файл Compose находится внутри модуля и подключается к уже существующей внешней сети; PostgreSQL/Б/поставщика он не создаёт. depends_on задаёт порядок запуска контейнеров, а не проверку готовности внешних зависимостей. Миграции выполняются до запуска admin-service, он сам DDL не выполняет. Для запуска инструмента через profiles используйте --profile tools при необходимости.

В примере порты привязаны к 127.0.0.1. ADMIN_PUBLIC_ORIGIN должен точно совпадать с адресом браузера, включая порт. HTTP с ADMIN_COOKIE_SECURE=false допустим для локального стенда; при HTTPS задайте true и соответствующий origin. МС2 не публикует порт хоста. Для внешней публикации владельцы стека настраивают ingress/TLS и сеть.

Создание хеша без установки Go:

```sh
read -r -s -p 'Пароль администратора: ' ADMIN_PASSWORD; printf '\n'
printf '%s' "$ADMIN_PASSWORD" | docker run --rm -i --entrypoint /admin-password credit-engine:local
unset ADMIN_PASSWORD
```

Инструмент принимает 8–72 байта через stdin и выдаёт bcrypt cost 12; пароль не передаётся аргументом командной строки. Хеш с символами $ в env-файле Compose заключайте в одинарные кавычки. ADMIN_EVENTS_TOKEN — самостоятельный случайный секрет 32–256 печатных ASCII-символов без пробелов, одинаковый у МС2 и МС3.

## Генератор

Сборка Dockerfile выполняет modelgen check и отклоняет неактуальные сгенерированные артефакты. Для работы с разрешённым checkout используйте инструмент с отдельным bind mount; runtime-контейнеры рабочие файлы не меняют:

```sh
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/workspace/credit-engine:ro" --entrypoint /modelgen credit-engine:local check -root /workspace/credit-engine
```

Генерация требует записи в этот же checkout; назначайте доступ rw только отдельной команде генерации. Комплект, полученный в админке, переносится в checkout по процедуре выпуска, после чего обязательны проверка генерации, сборка и тесты. Обновление DTO участников согласуется до включения новой модели.

## Для владельцев общего стека

- Образы/entrypoint и внутренние порты: МС1 8082, МС2 8083, МС3 8084.
- МС1: BANK_URL, STATEMENTS_URL; FACTS_URL обязателен, когда встроенный каталог использует новые факты.
- МС2: ADMIN_URL и ADMIN_EVENTS_TOKEN.
- МС3: ADMIN_DATABASE_URL, ADMIN_USERNAME, ADMIN_PASSWORD_HASH, ADMIN_EVENTS_TOKEN, ADMIN_PUBLIC_ORIGIN, ADMIN_COOKIE_SECURE, ADMIN_SCORING_URL.
- PostgreSQL хранит ревизии, версии, архивы, события и сессии; обеспечьте резервное копирование её данных и роль/права схемы.
- После развёртывания проверьте /healthz, вход, GET МС1 /api/v1/models и контрольные суммы модели. /healthz не подтверждает готовность внешних участников.
- Перезапуск МС2 сбрасывает учебное состояние банка, идемпотентные результаты и PENDING. Перед согласованной заменой контейнера учтите это ограничение и завершите необходимые повторы доставки.
- Общие Compose/Makefile/CI/миграции соседних сервисов настраивают их владельцы.
