# Проверка эквивалентности сгенерированной v2

До переключения конвейера проверяется именно [каталог сборки](15_compiled_models.md), а не только прочитанное JSON-определение. Старые эталоны и действующие классификаторы служат независимым сравнением; веса, ожидаемые значения и допуски не меняются ради переноса.

## Проверяемые уровни

| Уровень | Проверка |
|---|---|
| Определения | Go-конструкторы и канонические JSON v2 совпадают, SHA256/версии/типы и зависимости верны. |
| Анкета | 393 случая исходного корпуса через compiled Engine.EvaluateCriterion; сравниваются ID, answer, points/max. Семь null-случаев проверяют запрос обязательных данных до начисления. |
| Контроли | Все 17 нулевых контрольных пунктов, их сохранённые ответы и OTHER_OR_UNKNOWN при отсутствующем military_status. |
| Коэффициенты | Все 368 граничных значений и 31 расчётный пример через тот же исполнитель случаев, который использует полный Evaluate. |
| Итог | 14 границ округления/классов и 3 комбинации блоков через Classify, общий с полным Evaluate. |
| Особые случаи | Нулевые знаменатели/неположительные значения, null и специальные баллы, отрицательный чистый долг/капитал, убытки и порядок ручных причин. Финансовые состояния на нормализованных формах проверяются отдельно от согласованности самих форм. |
| Маршруты | Все 18 сценарных файлов, 17 единичных стопов и 2 случая неподтверждённого денежного стопа. |
| Полный процесс | Прежние тесты scoring/app с реально сгенерированным исполнителем, HTTP JSON, подбором, МС2, событиями, повторами/конкурентностью и ошибками зависимостей. |

## Полный процесс до постоянного подключения

Тестовая подстановка через Go overlay заменяет вызов Evaluator.Evaluate на адаптер общего расчёта с NewDefault. Она сохраняет техническую проверку А, один вызов Б при необходимости, обработку ошибок Б и перевод числового результата v2 в действующие DTO. Баллы, маршруты, финансовые расчёты и операции банка не подменяются. Исходные HTTP-тесты/проверки/эталоны остаются прежними; А/Б/уведомления используют их изолированные подмены.

Подстановка действует только в дочернем go test и сохраняет независимую проверку перехода. С пункта 13 рабочий Evaluator.Evaluate использует compiled-каталог постоянно; вся существующая приёмка scoring/app также исполняется обычным go test на этом пути, без подстановки. Дополнительная сгенерированная сборка проверяет полный HTTP-процесс с несколькими новыми версиями и поставщиком, сохраняя legacy v2 в том же каталоге.

## Условия прохождения

- Совпадают критерии/порядок, значения и null, баллы/максимумы, суммы/округление/классы, причины и маршруты.
- Подтверждённый стоп сохраняет приоритет над нехваткой данных; неподтверждённый CFADS не даёт отказ, D предшествует ручным основаниям.
- Не появляются лишние вызовы Б, банка или уведомлений; динамическое состояние и повторная выдача сохраняют прежние гарантии.
- Существующий числовой REST JSON сохраняется; boolean-расширение проверяется отдельно с сохранением этой совместимости.
- Повторная подготовка отчётности не использует устаревшие значения предыдущего комплекта.

Проверка запускается без реальной инфраструктуры. Успех этого этапа подтверждает перенос v2; новую модель с изменёнными правилами нужно проверять по её собственным утверждённым ожиданиям.
