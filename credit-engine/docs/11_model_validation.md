# Проверка модели перед выпуском

`model.Validate(definition, trustedCatalog)` в пакете `internal/model` возвращает ValidationResult: valid, issues и максимумы questionnaire_maximum/additional_maximum/total_maximum. Это общий валидатор для генератора и backend админки. Он не изменяет определение, не нормирует веса, не вызывает HTTP/БД/банк и не публикует модель.

Описание входа — в [формате модели](10_model_format.md). Успешное чтение JSON означает только допустимую форму черновика. Для выпуска обязательны `valid=true` и пустой список issues. Подключение к CLI и административным маршрутам выполняется при реализации этих компонентов; сейчас предоставлена чистая Go-функция.

## Проверяемые свойства

| Область | Что блокирует выпуск |
|---|---|
| Документ | Неподдерживаемая версия формата, непрочитываемая сериализация, null обязательных служебных списков, превышение размера/глубины. |
| Идентификация | Пустые/некорректные идентификаторы, неподдерживаемый тип заёмщика, дубли параметров/критериев/правил и локальных вариантов критерия. |
| Имена | Коллизии JSON-имён в одном объекте и имён генерируемых Go-полей, неэкспортируемые/зарезервированные Go-имена, недопустимый snake_case поставщика, переименование существующей привязки. |
| Источники | Неизвестная привязка APPLICATION/STATEMENTS/COMPUTED, несовместимые тип/единица, неизвестная зависимость каталога, новые строковые поля поставщика, отсутствие схемы активных фактов. |
| Домены | NaN/Inf, пустой числовой диапазон, недостижимый целочисленный диапазон, неверный/повторный enum, домен неподходящего типа. |
| Условия | Неподдерживаемый оператор/форма, отсутствующие/лишние операнды, неизвестные/отключённые параметры, несовместимые литералы/единицы, порядок над нечислом, неверная дата, дубли IN. |
| Зависимости | Отсутствующий параметр, активная зависимость от отключённого, неуказанные зависимости существующего расчёта, циклы, в том числе через required_when. |
| Ответы | Неизвестный параметр шаблона, произвольный вызов вместо `${parameter_id}`, незакрытый placeholder, пересечение условий выбора составного ответа. |
| Баллы | Отрицательные/нечисловые/превышающие максимум баллы, дробные баллы анкеты, неверный тип специального результата, неприменимые или недостижимые варианты/максимумы. |
| Шкалы | Пропуски и пересечения обычных/особых вариантов в их области применения; ни порядок, ни первое совпадение не скрывают ошибку. |
| Классы | Не A–D, дубли, неполная/пересекающаяся шкала 0..1000, неверный порядок D/C/B/A, отсутствие причины класса C/D. |
| Максимумы | Любое отличие от 750/250/1000 для каждой модели, включая 750+249, 751+250 и 760+240. |

Source catalog предоставляется доверенным Go-кодом существующих расчётов. Определение не может само объявить произвольную новую формулу доверенной. Binding фиксирует допустимый тип заёмщика либо общую привязку; известные пространства имён анкеты/показателей ИП и ЮЛ и формы Б также проверяются. Источник другого типа заёмщика нельзя применить, изменив только метаданные модели. JSON-имена в разных объектах не конфликтуют: например, revenue в предыдущей и текущей годовой форме остаются разными привязками. Отключение не удаляет объект и его историю; активные потребители отключённого параметра блокируются.

Максимумы считаются по активным критериям. Дробные баллы дополнительного блока допустимы; объявленные максимумы критериев целые, чтобы сохранять транспортный формат. Нормализация, уменьшение веса другого блока и разрешение выпуска по одному только общему итогу 1000 не выполняются.

## Проверка диапазонов

Валидатор разбивает объявленные домены на классы значений, неразличимых используемыми предикатами, и перебирает эти классы полностью. Это проверка предикатов, а не случайное тестирование нескольких чисел:

- включаются все числовые границы и пороги условий;
- у отдельных параметров проверяются точки и открытые интервалы между ними;
- для сравниваемых параметров сохраняются все достижимые взаимные порядки/равенства, с отдельными целочисленными опорами;
- арифметика числовых фактов соответствует конечным `float64`; соседние представимые значения находятся через Nextafter, без допуска epsilon;
- проверяются все enum/boolean-значения и отдельное неизвестное состояние;
- при неприменимом критерии начисление не проверяется как обязательное;
- подтверждённый special_case исключает обычную шкалу; перекрытие специальной и обычной ветви само по себе допускается именно как явно заданный приоритет;
- внутри выбранной шкалы два совпадения запрещены; ни одно совпадение при полностью известных значениях означает пропуск;
- неизвестность не считается нулём/false. При неизвестных нужных данных действуют объявленные requiredness/unknown_action, а не фиктивное покрытие известного диапазона.

При проверке достижимости учитывается обязательность участвующих параметров и зависимости required_when: неизвестный обязательный факт, который остановит расчёт на NEED_INFO, не может быть единственным способом получить объявленный максимум критерия.

Недостижимый активный критерий, недостижимый вариант и объявленный максимум, которого не достигает ни один допустимый вариант данного критерия, отклоняются. Это не проверка возможности одновременного достижения максимумов всех финансово связанных критериев: 750/250 проверяются как суммы объявленных максимумов по согласованной методике.

В целях ограничения затрат один документ допускает до 10000 узлов условий; глубина документа ограничена 64, размер — 4 MiB. Точный перебор ограничен 250000 посещённых состояний на модель и 64 независимыми параметрами одного критерия. Превышение даёт CONDITION_COMPLEXITY/COVERAGE_COMPLEXITY и блокирует выпуск. Частичная проверка никогда не возвращается как успешная. Черновик можно упростить структурно и проверить снова; веса не исправляются автоматически.

Числовое доказательство учитывает NumericKind доверенного источника. Границы сохраняются как точные десятичные токены, затем интерпретируются в представлении источника. Для INT64 проверяются все достижимые целые, в том числе между соседними float64 выше 2^53; для RATIONAL учитываются интервалы, в которых нет float64, но есть дроби. Для FLOAT64 сохраняются именно представимые бинарные значения. Сравнения нескольких параметров проверяются по точным граничным клеткам и возможным отношениям порядка, включая равенство и смешанные представления. Генерация представителей также расходует общий лимит состояний. Исчерпание лимита блокирует выпуск.

requires_checks проверяется на существование, повторы и отключение проверок; after_criterion — на допустимость в manual_reviews и наличие включённого критерия. Эти ссылки сохраняют зависимости подтверждённого денежного стопа и порядок причин v2.

## Адресные ошибки

Каждый Issue содержит JSON Pointer path, code, message. Например:

```json
{
  "path": "/criteria/2/cases/1/when",
  "code": "CASE_OVERLAP",
  "message": "Multiple ordinary cases match ..."
}
```

Диагностика диапазонов содержит контрпример из объявленных доменов. Это сгенерированные проверочные значения, не данные реальной заявки. Список ошибок упорядочивается детерминированно; входное определение остаётся прежним. Ошибки структуры/типов могут прекращать небезопасный дальнейший анализ, но такой результат всегда valid=false.

## Проверки реализации

Изолированные тесты проверяют адресные ошибки, все блокирующие максимумы, источники/зависимости/циклы, имена/типы, особые случаи/результаты, классы, неизвестность и безопасные шаблоны. Три фрагмента формата принимаются семантически и отклоняются именно как неполные по максимумам, поэтому не становятся случайными действующими версиями.

Проверка диапазонов сопоставляется с независимыми полными переборами: 120 детерминированных наборов правил на двух целых переменных и ещё 120 на трёх переменных в малом полностью перечислимом наборе соседних float64, включая смешанный целочисленный домен. Отдельно проверяются граничная точка, щель шириной в одно представимое значение, отсутствие значений между соседними float64 и целочисленный переход без ложной щели. Проверены детерминизм, неизменность входа и конкурентные вызовы без внешней инфраструктуры.

Полное совпадение расчёта v2 подтверждается последующими переносом и приёмкой моделей; успешный валидатор сам по себе не является доказательством эквивалентности всего процесса МС1/МС2.
