# modelgen и комплект релиза

`modelgen` проверяет определения, создаёт согласованный комплект Go/OpenAPI/Markdown, проверяет его актуальность и готовит ZIP. Рабочий МС1 использует встроенный Go-каталог; выполнение генератора не меняет уже запущенный процесс.

## Команды

Из каталога `credit-engine`:

```sh
go run ./cmd/modelgen validate
go run ./cmd/modelgen generate -release 2.0.0
go run ./cmd/modelgen check
go run ./cmd/modelgen archive
```

Из корня репозитория можно собрать/запустить инструмент с рабочим каталогом модуля либо передать готовому бинарному файлу `-root credit-engine`. Корнем должен быть реальный каталог `credit-engine` с соответствующим `go.mod`. Символические пути и Windows junction отклоняются.

| Команда | Результат |
|---|---|
| `validate` | Проверка модели, совместимости версий/схем и возможности генерации; файлы не меняются |
| `generate` | Канонические определения, сгенерированный Go, контракты, таблицы, изменения, манифесты и контрольные суммы |
| `check` | Сравнение ожидаемых байтов с файлами, включая отсутствующие/изменённые/лишние старые Go-файлы; запись не выполняется |
| `archive` | Неизменяемый `models/releases/<версия>.zip` и манифест подготовленного комплекта; рабочие исходники и текущая версия не переключаются |

Код завершения: 0 — успех; 1 — ошибочные данные/файлы/устаревший комплект/ошибка операции; 2 — неверный вызов. Ответ успешной операции и различия `check` выводятся как JSON. Ошибки идут в stderr. Подготовка комплекта отдельно от сборки, тестов и развёртывания.

## Каталог версий

После первой генерации входы по умолчанию — модели текущего `models/release.json`. До первого релиза берутся JSON-определения непосредственно из `models/`; подкаталог `examples` не включается. Версия релиза берётся из текущего манифеста либо явно задаётся `-release` при первом выпуске. `-notes` добавляет описание; при повторе уже подготовленного релиза сохраняется его прежний текст.

Новый состав задаётся полным перечнем повторяемых `-model`:

```sh
go run ./cmd/modelgen validate -model models/ip-v2.json -model models/legal-v2.json -model models/ip-v3.json
go run ./cmd/modelgen generate -release 2.1.0 -model models/ip-v2.json -model models/legal-v2.json -model models/ip-v3.json -notes "Добавлена новая модель ИП"
go run ./cmd/modelgen check
go run ./cmd/modelgen archive
```

`ip-v3.json` здесь обозначает самостоятельно подготовленное и проверенное новое определение. Генератор не придумывает параметры или веса. Добавление файла в каталог после первого выпуска само по себе не включает его в активный состав. До генерации при проверке/архивации нового состава нужно передавать тот же полный список.

Старые версии сохраняются в составе первой миграции; исключение оформляется явно составом следующего релиза. Изменение уже выпущенного определения требует новой версии модели. Версия схемы поставщика также не переиспользуется с другим составом/доменами. Имена версий переносимы между Windows/Linux: запрещены зарезервированные имена файлов, завершающая точка и различия только регистром.

## Содержимое и проверка

- Канонические `models/<версия модели>.json`.
- Статические Go-модели/каталог и именованные DTO/доступ к фактам.
- Основной и поставщицкий OpenAPI, Markdown с сохранённой ручной частью.
- `models/changes.md`: базовый релиз, описание и добавленные/изменённые/исключённые файлы с SHA256.
- `models/release.json`: текущий состав, версии/хеши моделей/схем, размеры/хеши файлов, ссылка/хеш базового релиза.
- `models/releases/<версия релиза>/manifest.json`: неизменяемая запись подготовленного комплекта.
- `models/SHA256SUMS`: хеши содержимого и обоих манифестов; сам индекс не включает свой хеш.

ZIP содержит те же артефакты с относительными разрешёнными путями. Порядок и права файлов фиксированы; дата ZIP — 1980-01-01. Используется STORE без сжатия, чтобы результат не зависел от версии компрессора. Дата запуска, случайные ID и абсолютные пути в архив не попадают. SHA256 архива возвращается командой; манифест также имеет отдельный хеш.

Повторный выпуск той же версии с теми же входами воспроизводит байты. Другое содержимое под той же версией отклоняется. Повторная генерация использует закреплённый базовый манифест, поэтому описание изменений не превращается в сравнение релиза с самим собой. Подготовленный архив не переписывается другим содержимым.

## Границы записи

Генератор пишет только фиксированные артефакты моделей, контрактов и таблиц внутри модуля. Пути с `..`, абсолютные пути, Git, произвольные исходники/README, ссылки и специальные файлы не являются допустимыми результатами. `os.Root` дополнительно удерживает операции внутри корня при разрешении путей.

Данные сначала готовятся и проверяются в памяти, затем помещаются во временную область `.work/modelgen`. Каждый файл заменяется атомарно; текущий манифест записывается последним. Операция не является транзакцией всей файловой системы: при ошибке она завершается ненулевым кодом, а `check` обнаруживает незавершённое применение. Повтор корректного выпуска позволяет завершить запись.

Удаляются только устаревшие Go-файлы прежнего манифеста с неизменённым SHA256. Изменённый или неизвестный файл блокирует применение. Исходные JSON прежних моделей, ручной текст документации и исторические комплекты сохраняются. Обычный `go build` генерацию не запускает; перед сборкой оператор явно выполняет `generate` и `check`.
