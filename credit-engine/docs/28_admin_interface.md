# Самостоятельный интерфейс админки

Интерфейс открывается в корне адреса `admin-service`. HTML, CSS и JavaScript встроены в Go-бинарник. Отдельные Node.js, сборка фронтенда и внешние CDN для запуска не требуются.

Настройки аккаунта, публичного адреса, cookie и БД описаны в [руководстве доступа](24_admin_access.md). Для локального HTTP явно задаются согласованные `ADMIN_PUBLIC_ORIGIN` и `ADMIN_COOKIE_SECURE=false`; для HTTPS cookie остаются Secure.

## Вход и навигация

Войдите настроенными логином и паролем. Поле пароля очищается после завершения запроса, сессия хранится в HttpOnly cookie, CSRF-токен — только в памяти страницы. При обновлении страницы сессия восстанавливается через API; при её завершении следующий защищённый запрос возвращает страницу входа. Кнопка «Выйти» отзывает сессию на сервере.

Основные разделы:

- **Модели** — опубликованные описания ИП/ЮЛ, версии и их состав;
- **Черновики** — текущие сохранённые изменения и история ревизий;
- **Проверка и выпуск** — симуляция, сравнение и подготовка комплекта;
- **Релизы** — подготовленные комплекты и отдельно версии/SHA работающего МС1;
- **Сообщения** — сохранённые события банка.

Списки имеют пагинацию. Поиск моделей/черновиков действует на текущей странице. Состояния загрузки, пустого списка и ошибки API отображаются явно; ошибочный запрос чтения можно повторить.

## Создание черновика

1. В списке моделей откройте нужную версию и нажмите «Копировать в черновик» либо используйте кнопку на карточке.
2. Укажите новую версию и основание изменения.
3. Откроется сохранённый черновик с номером ревизии и результатом общей проверки.

Кнопка «Создать черновик» создаёт новое описание: название, тип заёмщика, идентификатор, версия и основание. Оно сохраняется с пустыми параметрами/критериями/правилами. Ошибки такого промежуточного состояния показываются; выпуск требует выполнения общей проверки, в том числе 750/250/1000. По умолчанию финансовые правила и баллы не придумываются.

Опубликованные описания не редактируются напрямую. Подготовленный релиз не объявляется автоматически запущенной моделью.

## Просмотр и ревизии

Карточка показывает тип заёмщика, версию, автора, максимумы блоков, критерии и параметры. Именованные поля и источники доступны для проверки контракта; исходное описание можно раскрыть как JSON.

В черновике выберите сохранённую ревизию. Историческое описание открывается отдельно от текущего состояния; есть возврат к текущей ревизии. При длинной истории кнопка «Показать более ранние ревизии» загружает следующие страницы. Изменение черновика во время загрузки проверки не подменяет показанный номер ревизии.

## Числа и безопасность отображения

Числа модели разбираются и передаются как точные JSON-токены. int64 больше `2^53`, десятичные литералы, `false` и null не преобразуются через обычный браузерный float64 для сохранения. Максимумы блоков складываются целочисленно.

Данные модели отображаются текстовыми DOM-узлами. Строки с HTML не выполняются; действует CSP без inline scripts/eval, защита от встраивания во фреймы и `no-store` для страницы/ресурсов. Служебные файлы проекта через статические маршруты не доступны.

Текущий черновик редактируется формами параметров/баллов, проверок/правил и классов; исторические ревизии остаются для чтения. Полное руководство — docs/35_administrator_guide.md.

Проверка включает Go-тесты встроенных ресурсов/заголовков, JavaScript-тесты точности/строгости JSON и настольные браузерные сценарии против изолированного admin-service/PostgreSQL: вход, неверный пароль, ИП/ЮЛ, редакторы/ревизии, симуляция/релиз, сообщения, ошибка/повтор API, отзыв сессии и выход. Мобильная версия не входит в целевую поставку.
