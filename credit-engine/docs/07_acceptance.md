# Приёмочные проверки MVP

Тесты выполняются без работающей инфраструктуры. Бизнес-сервисы получают in-memory зависимости; HTTP-обработчики проверяются через httptest.NewRecorder; REST-клиенты — через подменный http.RoundTripper. Процессы А/Б/МС3 для юнит-тестов не нужны.

## Сценарии

| История | Обязательные ожидания |
|---|---|
| UC-01, ИП и ЮЛ | NEED_INFO, score=null; нет обращения в МС2 и события МС3. Пропуск не превращается в 0. |
| UC-02, ИП и ЮЛ | REJECTED по классу D; ранний стоп отдельно. Нет МС2 и события. Стоп выше нехватки данных. Неполный или неподтверждённый денежный набор с F ≤ 0 сам по себе стопом не считается. |
| UC-03, ИП и ЮЛ | UNDER_REVIEW/BORROWER, вызван только ручной маршрут МС2; финансовая проекция не запускалась, банк не изменился. Событие BORROWER_REVIEW. |
| UC-04, ИП и ЮЛ | Реально рассчитаны баллы и подбор; ISSUED → APPROVED; банк и реестр изменились ровно один раз; событие LOAN_ISSUED. |
| UC-05, ИП и ЮЛ | Предложение посильно, но провален Н1.0 или Н2: UNDER_REVIEW/BANK; состояние прежнее; событие BANK_REVIEW с проблемными значениями. |
| UC-06 | Две заявки в одном состоянии: выдача 3 млн оставляет 7 млн; вторая на 2 млн привела бы к 5 млн, фактически остаётся 7. На чистом банке вторая одобряется. |
| AUTO: срок и ставка | auto_ip_extend_term: 3 млн, запрос 12 мес. → выбрано 24 мес. и 23,75%; сохранено ≥90% максимального NPV. |
| AUTO: сумма | auto_le_reduce_amount: запрос 5 млн → 3,13 млн; минимально приемлемая сумма соблюдена. |
| AUTO: нет условий | Минимальная сумма 4 млн не помещается либо клиент допускает ставку только до 10%: ручной маршрут, а не отказ или выдуманное предложение. |

## Границы и независимые проверки

- Баллы: все варианты 31/27 анкетных пунктов и все пороги 13/18 дополнительных критериев; суммы максимумов 750/250 и 1000, 549/550/649/650/799/800, 647,5 → 648; отсутствие промежуточного округления. Положительные/нулевые знаменатели и специальные правила из документа скоринга.
- Данные: подтверждённый ноль/false против null/пропуска; 12/36 периодов, повтор месяца, неактуальные факты, два года Б, RUB/THOUSAND_RUB, несходящийся баланс/ОФР. ИП не вызывает Б.
- Подбор: клиентские границы, нулевой процент в аннуитете, точный желаемый верх вне шага 10 тыс., точный минимум клиента, максимум ставки вне шага 25 б.п., отрицательный/нулевой запас платежа, пустой набор.
- Выбор: максимальная сумма раньше максимизации NPV; ровно 90% проходит, ниже не проходит; минимальная переплата внутри допустимого набора; стабильные дополнительные критерии. Суммы разных размеров по переплате не сравниваются.
- Экономика: общая функция МС1/МС2; FTP для >24 месяцев; q не списывается повторно в NPV; выделенный капитал не списывается вторично из K0; NPV округлён до копейки один раз и 0 блокирует.
- Банк: пороги нормативов включительно, недопустимые знаменатели, изменение Н6 чужой группы, вход всей группы в Н7 из-за снижения K0, рост Н12 без новых вложений, запрет выдачи. Ручной маршрут не вызывает проекцию.
- Повторы: одинаковая заявка — один кредит и одно подтверждённо доставленное событие; другая сделка под тем же ID — 409. При потерянном ответе повтор не списывает второй раз.
- Уведомление: сбой МС3 оставляет PENDING; уже выданный кредит не отменяется; повтор отправляет прежний event_id и не меняет банк.
- Конкурентность: два независимых кредита по 3 млн на начальных 10 млн при минимуме 6 млн — ровно одна выдача, второе рассмотрение. Порядок победителя не фиксируется, остаток 7 млн. Выполнить с -race.
- Транспорт: неверный JSON/тип, бизнес-пропуски, ошибка Б/МС2, 404 Б, policy mismatch. 502/504 не превращаются в REJECTED/UNDER_REVIEW; 409 от МС2 сохраняется как 409. Чужой borrower_id/application_id в ответе зависимости даёт 502.
- Кредитные ставки REST: 1 означает 1%, 100 означает 100%, 23.75 означает 23,75%; 0 и 100 допустимы, отрицательное значение, больше 100 или точность выше двух знаков дают 422. Проверить преобразование в долю единицы для расчётов и возврат процентов в ответе. Долг больше суммы платежей за 36 месяцев сам по себе не является противоречием.

В эталонах сравнивать статусы, коды причин, поля, числовые значения и побочные действия. Четыре message клиента фиксированы; формулировки reason.message/check.detail могут быть равнозначными, но должны оставаться понятными. Допуск по деньгам 0,01 руб., отношениям 10^−9; проверки порогов кредитной политики выполняются до форматирования.

Агент обязан записать фактически выполненные команды и результаты в agent_log.md. Тесты DTO из проверки этого комплекта не подтверждают реализацию бизнес-сервисов.


## Обязательное дополнение по скорингу v2

Каждый пункт справочника должен иметь тесты начисления по исходным полям; контрольные вопросы — тесты маршрута. Проверить null против 0/false, неизвестный enum (422), неподходящую/двойную ветку scoring, условность location_stability_months и необязательность military_status. Одна исходная просрочка/налог/коэффициент не начисляется повторно.

Каждый стоп из раздела 6 документа скоринга проверить отдельно на иначе сильных ИП/ЮЛ: REJECTED, score=null, нет Б для раннего стопа, нет МС2/МС3 и изменения банка. NONPOSITIVE_VERIFIED_CFADS проверять для F=0 и F<0; такой же набор с пропуском/неподтверждённостью → NEED_INFO. Дни 29/30 и 89/90 проверяются явно. Возраст/автомобиль/семейный статус не образуют новых стопов.

Фактическая неполнота форм Б при documents_complete=true → NEED_INFO, никакого 30 за комплект по одному заявлению А. Проверить RUB/THOUSAND_RUB на одинаковых результатах, отрицательный допустимый капитал/прибыль, нулевые знаменатели и отсутствие NaN/Inf. Слабый дополнительный блок не исключается; класс определяется только общим итогом, кроме приоритетных правил. Пример сумм: анкета 500 + показатели 200 → B; анкета 600 + показатели 0 → C; отдельного порога 750-блока нет.

Все тесты рассчитывают баллы реальным Go-кодом. Примеры JSON/ожидания не являются заменой реализации. Ответ А с добавленными готовыми score/grade/ratio не должен менять начисления: использовать только типизированные исходные поля.
