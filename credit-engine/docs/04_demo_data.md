# Воспроизводимые примеры окончательной версии

В эталонах дата оценки — 23.10.2026, часы событий — 2026-10-23T12:00:00Z. [scenarios.json](../testdata/scenarios.json) описывает 17 независимых сценариев с 18 заявками; UC-06 состоит из двух последовательных шагов. Пути в manifest разрешаются относительно папки testdata/.

Кредитные ставки max_annual_rate/annual_rate во всех примерах выражены в процентах: 24 = 24%, 23.75 = 23,75%. calculation_report.json сохраняет автономные расчётные эталоны; он не является отчётом о запуске сервисов.

| Расположение | Назначение |
|---|---|
| decisions/*.json → request | Настоящее тело POST /api/v1/decisions от А. |
| service_b_response | Подменный ответ Б; ИП его не использует. |
| expected.response | Ожидаемый DecisionResponse. Подбор уже выполнен по реальным исходным данным. |
| expected.bank_check_request / manual_review_request | Ожидаемое обращение МС1 в МС2; один из маршрутов либо оба null. |
| expected.statements_called / ms2_called / bank_projection_called / admin_called | Ожидаемые вызовы зависимостей для проверки моками. |
| expected.notification | Ожидаемый AdminEvent только от МС2. |
| expected.selection | Внутренний расчёт выбранного варианта; не вход от А и не часть публичного ответа. |
| expected.bank_state_before / bank_state_saved | Снимки для проверки изменения/отсутствия изменения. |
| bank/*.json | 7 изолированных запросов МС2, включая фиксированную сделку 24% и отрицательный/нулевой NPV. |
| scoring_boundaries.json / unit_cases.json | Дополнительные табличные и сценарные условия тестов. |
| calculation_report.json | Фактические результаты автономных расчётов, без запуска сервисов. |

Перед каждым независимым сценарием загружать указанный config/bank.*.json и общую policy.json. Между двумя шагами UC-06 состояние не сбрасывать. Повтор второй заявки отдельно на начальном банке должен пройти.

## Воспроизведение через API

Из каталога credit-engine/ на Linux запустите полный изолированный стенд:

```sh
sh scripts/verify.sh
```

Команда запускает все три сервиса, PostgreSQL и HTTP-поставщиков тестовых данных, затем автоматически выполняет все истории manifest и банковские примеры. Проверяются ответы, исходящие запросы, банк, сохранённые события и идентичные повторы. Устройство стенда, отдельный запуск с сохранением контейнеров и отчёты описаны в [воспроизводимой приёмке](37_reproducible_acceptance.md).

При ручном запуске задайте МС1 DEMO_EVALUATION_DATE=2026-10-23 и МС2 BANK_STATE_FILE с профилем из manifest до старта контейнеров. Запущенный МС2 использует текущее UTC для occurred_at; фиксированное время эталонов применяется в Go-тестах с подменой часов. Отправляется только поле request, а не файл с ожидаемыми результатами. Файлы примеров не читаются работающим МС1; service_b_response должен вернуть внешний Б или тестовый поставщик. Для ИП Б не вызывается. При недоступности МС3 бизнес-решение сохраняется, доставка остаётся PENDING.

Для UC-06 последовательно отправляются request из uc06_01_ip_issued.json и uc06_02_le_bank_review.json на одном МС2 со стартовым default-профилем. После первой заявки Cash=7 млн, после второй он остаётся 7 млн. На новом МС2 с default-профилем отдельно отправленная вторая заявка одобряется, Cash=8 млн. Независимые истории требуют нового МС2; идентичный повтор на прежнем экземпляре возвращает сохранённый результат. Стенд делает эти перезапуски автоматически.

## Ожидаемые результаты

Баллы пересчитаны по v2 (анкета + показатели): отказ ИП 275+132,5→408, ЮЛ 390+106,25→496; ручной класс C — ИП 450+177,5→628, ЮЛ 505+121,25→626; обычное одобрение — 991/976. Банк может остановить и заёмщика класса A/B. После полной оптимизации обычные предложения 3 млн из набора выбираются на 22 месяца под 24%, а не из старого фиксированного кандидата на 24 месяца.

Примеры главной функции:

- auto_ip_extend_term: 3 млн на 12 месяцев запрошено; максимум клиента 24 месяца. Выбрано 24 месяца под 23,75%, NPV 111 283,59 руб. против максимума 118 945,54 руб.
- auto_le_reduce_amount: запрос 5 млн, минимум 2,5 млн. Выбрано 3,13 млн на 24 месяца под 20,25%.
- auto_ip_no_acceptable_amount: минимум клиента слишком велик → ручной маршрут.
- auto_le_rate_too_low: ни одна допустимая ставка не даёт положительного NPV → ручной маршрут.

В базовых заявках максимальная ставка 24% — пожелание синтетического клиента, а не фиксированная ставка банка. В auto_le_rate_too_low клиент ограничил её 10%; отдельные проверки МС2 также используют другие ставки. Реальные тесты должны использовать и иные ограничения, включая границу, не кратную шагу.

В старом демопакете предложения задавались заранее. Теперь основной набор проверяет полный подбор; отрицательный NPV отдельно проверяет МС2, потому что корректный оптимизатор такой кандидат не отправит. Тип IP заменён на SOLE_PROPRIETOR; кредитный отказ — REJECTED. Текущая модель v2 отдельно начисляет 750 за анкету и 250 за расчёты; старые балльные эталоны заменены.

Сравнивать бизнес-поля и действия с допусками из manifest. Идентификаторы детерминированы: loan_id = "loan-" + application_id, event_id = application_id + ":" + kind. Формулировки причин могут быть равнозначными; четыре клиентских статуса/message и коды причин проверяются точно.

scoring_boundaries.json содержит 393 примеров ответов/порогов анкеты и 368 числовых проверок дополнительных показателей. unit_cases.json содержит 17 независимых однофакторных стоп-тестов и отдельные проверки неподтверждённого CFADS. В set путь monthly_history[*].field означает изменение этого поля во всех 12 месяцах базового request; остальные пути — обычные точечные изменения. scoring_reference_examples.json фиксирует 31 пример из утверждённого справочника. Эти JSON используются только тестами, не конфигурацией расчёта.
