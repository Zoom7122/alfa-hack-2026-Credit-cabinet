# Credit Engine

Учебный компонент кредитного кабинета для ИП и юридических лиц. Три самостоятельных HTTP-сервиса на Go и Gin:

| Сервис | Назначение | Внутренний порт |
|---|---|---|
| scoring-service (МС1) | Проверка данных, скоринг и подбор условий | 8082 |
| bank-state-service (МС2) | Состояние банка, учёт учебной выдачи, доставка событий | 8083 |
| admin-service (МС3) | Редактор моделей, предварительный расчёт, выпуск и сообщения | 8084 |

Рабочий скоринг статичен: новая модель применяется после генерации, сборки и развёртывания. Админка не изменяет работающий МС1 на лету. Интерфейс предназначен для настольного браузера.

## Запуск в Linux через Docker

Из каталога credit-engine:

```sh
docker build -t credit-engine:local .
```

Образ содержит три сервиса, admin-migrate, modelgen и admin-password. Локальные Go и Node для запуска не нужны. По умолчанию запускается /scoring-service; остальные процессы выбираются через --entrypoint. Конфигурация находится в /app/config.

Подключите PostgreSQL, поставщика отчётности Б и при необходимости агрегатора дополнительных фактов к сети стека. Заполните локальный файл .env.admin по config/admin.env.example:

| Переменная | Назначение |
|---|---|
| CREDIT_ENGINE_NETWORK | Имя существующей Docker-сети |
| CREDIT_RUNTIME_DATABASE_URL | PostgreSQL URL общей схемы runtime; применить runtime-migrate перед запуском |
| ADMIN_DATABASE_URL | PostgreSQL URL для административной схемы |
| ADMIN_USERNAME | Логин администратора |
| ADMIN_PASSWORD_HASH | bcrypt-хеш пароля, cost 10–14 |
| ADMIN_EVENTS_TOKEN | Общий секрет МС2/МС3: 32–256 печатных ASCII-символов без пробелов |
| ADMIN_PUBLIC_ORIGIN | Точный адрес кабинета, например http://localhost:8084 |
| ADMIN_COOKIE_SECURE | false для локального HTTP; true при HTTPS |
| STATEMENTS_URL | Базовый HTTP(S) URL поставщика отчётности |
| FACTS_URL | URL агрегатора; необходим, если встроенные модели используют новые факты |

Для получения хеша передайте пароль через stdin утилите образа:

```sh
read -r -s -p 'Пароль: ' ADMIN_PASSWORD; printf '\n'
printf '%s' "$ADMIN_PASSWORD" | docker run --rm -i --entrypoint /admin-password credit-engine:local
unset ADMIN_PASSWORD
```

Хеш с символами $ в env-файле Compose заключайте в одинарные кавычки. Примените миграции и запустите сервисы:

```sh
docker compose --env-file .env.admin -f compose.credit-engine.yaml run --rm runtime-migrate up
docker compose --env-file .env.admin -f compose.credit-engine.yaml run --rm admin-migrate up
docker compose --env-file .env.admin -f compose.credit-engine.yaml up -d
curl http://localhost:8082/healthz
curl http://localhost:8084/healthz
```

Пример публикует порты только на 127.0.0.1. Откройте http://localhost:8084 и войдите настроенной учётной записью. Для другого адреса измените ADMIN_PUBLIC_ORIGIN и при необходимости ADMIN_PORT. Миграции выполняются отдельно до запуска админки; рабочий сервис DDL не применяет. Подключаемый Compose не создаёт PostgreSQL и внешних поставщиков.

Все сервисы возвращают /healthz с HTTP 200 и {"status":"ok"}. Метод проверяет процесс, доступность внешних зависимостей им не подтверждается. В конечном образе нет shell/curl.

## Административный кабинет

1. Скопируйте опубликованную модель в черновик с новой версией либо создайте пустую.
2. Настройте параметры, баллы, проверки, стопы, ручные основания и классы. Новые факты поставщика — именованные числа или boolean.
3. Максимумы каждой модели должны быть ровно 750 + 250 = 1000. Промежуточный черновик можно сохранить, неверный комплект выпустить нельзя.
4. Сохраните ревизию с основанием. Несовпадение ожидаемой ревизии даёт конфликт без перезаписи чужих изменений.
5. На экране «Проверка и выпуск» загрузите JSON-набор с явной датой, выполните расчёт и сравнение.
6. Выберите полный состав версий, просмотрите генерируемые таблицы/схемы, подготовьте и скачайте ZIP.
7. Перенесите согласованный комплект в исходники, проверьте, соберите и разверните новую версию. Поставщик должен поддерживать новую схему до включения модели.

Экран «Сообщения» показывает сохранённые события МС2 с фильтрами и подробностями. Изменение события и команды принятия решения не предусмотрены. Экран «Релизы» отдельно показывает подготовленные комплекты и версии/SHA-256, полученные от работающего МС1.

Руководства находятся в docs/: 29_parameter_editor.md, 30_rules_editor.md, 31_simulation_release_ui.md, 32_events_runtime_ui.md, 33_container_delivery.md, 35_administrator_guide.md и 36_release_and_integration.md.

## API и данные

Основной контракт — [OpenAPI](contracts/openapi.json), типы — [contracts/contract.go](contracts/contract.go). Подключение участников описано в [интеграции](docs/05_integration.md), поля и баллы — в [методике скоринга](docs/02_inputs_and_scoring.md). Административный контракт: contracts/admin.openapi.json; контракт метаданных МС1: contracts/scoring_metadata.openapi.json.

| Сервис | Метод | Назначение |
|---|---|---|
| МС1 | POST /api/v1/decisions | Оценить заявку и получить решение |
| МС1 | GET /api/v1/models | Получить версии/SHA встроенного каталога |
| МС2 | POST /api/v1/bank/check-and-issue | Проверить и учесть сделку |
| МС2 | POST /api/v1/bank/manual-reviews | Передать на рассмотрение |
| МС2 | GET /api/v1/bank/state | Прочитать учебное состояние |
| МС3 | /api/admin/v1/* | Защищённый административный API |
| МС3 | POST /api/v1/credit-events | Сохранить событие МС2 с Bearer-авторизацией |

Минимальный запрос:

```sh
curl -H 'Content-Type: application/json' \
  -d '{"application_id":"example-001","borrower":{"id":"borrower-001","type":"SOLE_PROPRIETOR"}}' \
  http://localhost:8082/api/v1/decisions
```

Он возвращает NEED_INFO. Для полного расчёта нужны анкета, финансовая история, условия и подтверждения; для ЮЛ — также два завершённых годовых комплекта отчётности Б. Новые факты МС1 сам получает одним запросом к агрегатору. Полные примеры находятся в testdata/decisions, наборы симуляции — testdata/simulation.

Кредитная ставка передаётся в процентах: 1 = 1%, 23.75 = 23,75%, 100 = 100%. Диапазон 0–100 включительно, до двух знаков после точки. Денежные суммы запроса — целые рубли; даты — YYYY-MM-DD. Пропуск/null не превращается в 0/false.

Версию новой модели указывайте явно в model_version. Прежний формат без версии использует v2; неизвестная версия не заменяется последней. Повтор должен сохранять версию и исходные данные.

| Статус МС1 | Значение |
|---|---|
| NEED_INFO | Требуются данные; итогового скоринга/условий нет |
| REJECTED | Подтверждённый стоп либо класс D |
| UNDER_REVIEW | Рассмотрение заёмщика либо банковское ограничение |
| APPROVED | Учебная выдача учтена, условия подтверждены |

Бизнес-результаты имеют HTTP 200. Ошибки JSON/данных/конфликта/зависимости возвращаются отдельно как application/problem+json со статусами 400/422/409/502/504; внутренние ошибки — 500. Успешная симуляция модели не подтверждает выдачу.

## Настройки и сохранность

МС1: BANK_URL, STATEMENTS_URL, FACTS_URL, POLICY_FILE, BANK_TIMEOUT=4s, STATEMENTS_TIMEOUT=2s, FACTS_TIMEOUT=2s, HTTP_WRITE_TIMEOUT=15s. DEMO_EVALUATION_DATE задаёт явную дату только для демонстрационных данных.

МС2: ADMIN_URL, ADMIN_EVENTS_TOKEN, POLICY_FILE, BANK_STATE_FILE, ADMIN_TIMEOUT=2s, HTTP_WRITE_TIMEOUT=15s. Снимки банка входят в config/. Политика МС1 и МС2 должна совпадать.

МС3: настройки доступа из таблицы выше, ADMIN_SCORING_URL для метаданных МС1, ADMIN_SCORING_TIMEOUT=2s, ADMIN_SESSION_TTL=1h, ADMIN_DATABASE_TIMEOUT=5s, ADMIN_REQUEST_TIMEOUT=30s, HTTP_WRITE_TIMEOUT=45s.

Базовые URL не содержат учётных данных, query или fragment. В Docker localhost обозначает текущий контейнер; используйте сетевые имена зависимостей. HTTP_WRITE_TIMEOUT должен покрывать последовательные обращения; общий административный тайм-аут должен превышать тайм-аут получения метаданных.

PostgreSQL сохраняет черновики, ревизии, версии, архивы, события и сессии админки. Состояние банка, результаты операций и исходящие события сохраняются в PostgreSQL в схеме credit_engine_runtime. Перезапуск сохраняет лимиты и учтённые выдачи. Для runtime-сервисов требуется DATABASE_URL и миграции общей схемы из модуля db. Недоставка уведомления не отменяет выдачу; идентичный повтор операции повторяет только недоставленное событие.

Для остановки:

```sh
docker compose --env-file .env.admin -f compose.credit-engine.yaml down
```

Данные внешней PostgreSQL этой командой не удаляются. Реальные выплаты, подпись, ML и изменение модели в работающем МС1 в MVP не входят.

## Комплексная проверка

Из каталога credit-engine/ на Linux с Docker Engine и Compose:

```sh
sh scripts/verify.sh
```

Команда собирает образ, запускает три сервиса с отдельной тестовой PostgreSQL и подменными внешними поставщиками, выполняет Go/race/integration, проверки браузера и все сценарии из testdata/. Тестовый стек удаляется при завершении. Подробности и параметры — в docs/37_reproducible_acceptance.md.

Надёжная отправка с `Idempotency-Key`, контракт `input_snapshot` и масштабирование описаны в [скоринговом конвейере](../docs/scoring-dispatch.md).
