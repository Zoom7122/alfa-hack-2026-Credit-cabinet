# Credit Engine

Компонент учебного кредитного кабинета для оценки заявок индивидуальных предпринимателей и юридических лиц. Состоит из двух HTTP-сервисов на Go и Gin:

| Сервис | Назначение | Адрес по умолчанию |
|---|---|---|
| `scoring-service` (МС1) | Оценка заёмщика и подбор условий кредита | `:8082` |
| `bank-state-service` (МС2) | Проверка сделки на состоянии банка и учёт учебной выдачи | `:8083` |

МС1 проверяет исходные сведения, рассчитывает скоринг, подбирает одно предложение и получает решение МС2. МС2 хранит состояние банка в памяти, учитывает учебную выдачу и отправляет события административному сервису МС3.

## Запуск

Требуется Go 1.26.8 или новее. Все команды выполняются из каталога `credit-engine/`.

В первом PowerShell-терминале запустите сервис оценки:

```powershell
$env:STATEMENTS_URL = 'http://statements:8080'
go run ./cmd/scoring-service
```

Во втором терминале запустите сервис состояния банка:

```powershell
$env:ADMIN_URL = 'http://admin:8080'
go run ./cmd/bank-state-service
```

`STATEMENTS_URL` — базовый URL поставщика бухгалтерской отчётности, `ADMIN_URL` — базовый URL сервиса административных уведомлений. Замените адреса из примеров адресами своих сервисов. Эти внешние компоненты в поставку Credit Engine не входят; их доступность при запуске не проверяется.

Проверка работоспособности:

```powershell
Invoke-RestMethod http://localhost:8082/healthz
Invoke-RestMethod http://localhost:8083/healthz
```

Оба сервиса возвращают HTTP 200 с телом:

```json
{"status":"ok"}
```

`/healthz` проверяет работающий процесс; доступность Б, МС2 и МС3 этой проверкой не подтверждается.

Для остановки используйте `Ctrl+C`.

## Настройки

| Переменная | Сервис | Значение по умолчанию / назначение |
|---|---|---|
| `SCORING_ADDR` | МС1 | `:8082` |
| `BANK_ADDR` | МС2 | `:8083` |
| `BANK_URL` | МС1 | `http://localhost:8083` |
| `STATEMENTS_URL` | МС1 | Обязательный базовый HTTP(S) URL поставщика отчётности |
| `ADMIN_URL` | МС2 | Обязательный базовый HTTP(S) URL административного сервиса |
| `POLICY_FILE` | Оба | `config/policy.json` |
| `BANK_STATE_FILE` | МС2 | `config/bank.default.json` |
| `DEMO_EVALUATION_DATE` | МС1 | Фиксированная дата оценки в формате `YYYY-MM-DD`; по умолчанию текущая дата UTC |
| `BANK_TIMEOUT` | МС1 | `4s` |
| `STATEMENTS_TIMEOUT` | МС1 | `2s` |
| `ADMIN_TIMEOUT` | МС2 | `2s` |
| `HTTP_WRITE_TIMEOUT` | Оба | `15s` |

Относительные пути к файлам конфигурации разрешаются от текущего рабочего каталога. Политика и начальное состояние банка проверяются до открытия HTTP-порта; некорректная конфигурация завершает запуск с ошибкой.

Базовые URL могут содержать префикс пути, но не учётные данные, параметры запроса или fragment. Тайм-ауты задаются положительными длительностями, например `2s`. `HTTP_WRITE_TIMEOUT` МС1 должен превышать сумму `STATEMENTS_TIMEOUT` и `BANK_TIMEOUT`, а МС2 — `ADMIN_TIMEOUT`. При изменении настроек оставляйте вызову МС1 → МС2 время на обращение МС2 к административному сервису.

## API

Схемы запросов и ответов описаны в [OpenAPI](contracts/openapi.json), Go-типы — в [contracts/contract.go](contracts/contract.go).

| Сервис | Метод и путь | Успешный ответ |
|---|---|---|
| МС1 | `POST /api/v1/decisions` | `200 DecisionResponse` |
| МС2 | `POST /api/v1/bank/check-and-issue` | `200 BankCheckResponse` |
| МС2 | `POST /api/v1/bank/manual-reviews` | `202 ManualReviewResponse` |
| МС2 | `GET /api/v1/bank/state` | `200 BankStateResponse` |
| Оба | `GET /healthz` | `200 {"status":"ok"}` |

Клиент отправляет заявку в МС1. Маршруты МС2 предназначены для межсервисного взаимодействия; чтение состояния позволяет наблюдать учебные изменения банка. Пути Б и МС3 в OpenAPI описывают контракты внешних участников и не обслуживаются этими двумя сервисами.

### Отправка заявки

Минимальный технически корректный запрос:

```json
{
  "application_id": "application-001",
  "borrower": {
    "id": "borrower-001",
    "type": "SOLE_PROPRIETOR"
  }
}
```

Он возвращает `NEED_INFO` со списком недостающих сведений. Для расчёта нужны исходная анкета, условия кредита, подтверждения и финансовые данные: [описание входов и скоринга](docs/02_inputs_and_scoring.md). Для ЮЛ дополнительно запрашиваются два завершённых годовых комплекта отчётности Б; ИП поставщика Б не вызывает.

Полный [пример заявки ИП](testdata/decisions/uc04_ip_approved.json) можно отправить из PowerShell. Перед запуском МС1 установите `$env:DEMO_EVALUATION_DATE = '2026-10-23'`, чтобы даты примера соответствовали дате оценки. Затем в другом терминале из каталога `credit-engine/`:

```powershell
$example = Get-Content -Raw -Encoding UTF8 testdata/decisions/uc04_ip_approved.json | ConvertFrom-Json
$body = $example.request | ConvertTo-Json -Depth 100
Invoke-RestMethod -Method Post -Uri http://localhost:8082/api/v1/decisions `
  -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

### Результат заявки

Все бизнес-результаты МС1 возвращаются с HTTP `200`:

| `status` | Сообщение | Смысл |
|---|---|---|
| `NEED_INFO` | Требуется дополнительная информация | Нужны дополнительные или уточнённые сведения; `score` и `terms` равны `null`. |
| `REJECTED` | Отклонено | Подтверждённый стоп либо класс D; условия кредита не предлагаются. |
| `UNDER_REVIEW` | Заявка на рассмотрении | `review_reason=BORROWER` — индивидуальная оценка; `BANK` — банковское ограничение. При `BANK` выбранные условия показаны с `terms_confirmed=false`. |
| `APPROVED` | Одобрено | Учебная выдача уже учтена; заполнены условия, платёж, переплата и `loan_id`, `terms_confirmed=true`. |

Для скоринга используются 750 анкетных и 250 финансовых баллов. Подбор выбирает наибольшую посильную сумму, затем минимальную переплату среди вариантов с NPV не ниже 90% максимального для этой суммы. Проверка выбранной сделки банком выполняется отдельно: [методика подбора](docs/06_offer_selection.md). Банковские агрегаты, нормативы и внутренний аудит подбора в ответ МС1 не включаются.

Технические ошибки возвращаются в формате `Problem` с `Content-Type: application/problem+json`: `400` — JSON/тип или обязательный конверт, `422` — недопустимое значение, `409` — конфликт заявки/политики, `502` — ошибка зависимости, `504` — тайм-аут, `500` — внутренняя ошибка. Они не являются кредитным решением.

Например, недопустимая ставка возвращает HTTP 422:

```json
{
  "type": "about:blank",
  "title": "Unprocessable Entity",
  "status": 422,
  "code": "INVALID_VALUE",
  "detail": "Unprocessable Entity",
  "fields": ["credit_request.max_annual_rate"]
}
```

### Единицы данных

Кредитные ставки `max_annual_rate` и `annual_rate` передаются в процентах: `1` означает 1%, `23.75` — 23,75%, `100` — 100%. Допустимый диапазон — от 0 до 100 включительно, точность — до двух знаков после точки. Пример выбранных условий по контракту:

```json
{
  "amount_rub": 3000000,
  "term_months": 24,
  "annual_rate": 23.75
}
```

Денежные суммы запроса задаются целыми рублями, сроки — целым числом месяцев. Нормативы и экономические коэффициенты сохраняют формат долей единицы: `0.30` означает 30%.

## Повторы и состояние

`application_id` идентифицирует заявку. До первого обращения в МС2 недостающие сведения можно дополнить под прежним ID. После получения терминального результата используйте новый ID для другой оценки. Идентичный повтор операции МС2 возвращает сохранённый результат; изменённые условия или маршрут под тем же ID дают `409`.

МС2 отправляет в МС3 события о выдаче, ручном рассмотрении и банковской проблеме. Сбой доставки оставляет `notification_status=PENDING` в ответе МС2 и не отменяет выдачу. Повтор той же операции повторяет недоставленное событие с прежним `event_id`; подтверждённое событие повторно не отправляется. МС3 должен принимать повторные `event_id` идемпотентно.

Состояние банка, результаты операций и события хранятся в памяти. Перезапуск МС2 загружает стартовый снимок заново. Реальных перечислений денег, подписания договора и последующего решения сотрудника этот MVP не выполняет.
