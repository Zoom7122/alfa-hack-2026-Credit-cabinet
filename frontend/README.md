# Frontend — умный кредитный кабинет

React 19 + TypeScript + Vite, UI-кит Альфа-Банка `@alfalab/core-components`, стили — обычный CSS по БЭМ на токенах кита (`@alfalab/core-components-vars`).

## Запуск

```bash
npm ci
npm run dev        # http://localhost:5173
```

## API

Источник правды — живой сервис сбора данных [data-collector](../data-collector/README.md) (спецификация `../data-collector/docs/swagger.yaml`). Контракт `../api/openapi.yaml` соблюдать не обязательно: фронт переделывается под то, что есть в data-collector.

Что работает с живым data-collector (`VITE_COLLECTOR_MOCK=false`, стек поднят `make up`), а что пока только на моках MSW:

| Экран | Живой сервис | Только мок |
|---|---|---|
| Вход, профиль | список тестовых пользователей, вход, `/me` (токен `mock.<user_id>`) | — |
| Главная | список заявок компании (`GET /applications`), карточка компании (`GET /applicants`) | демо-заявки 07–18, задачи |
| Подбор продукта и калькулятор (03) | каталог по цели и типу компании, расчёт платежа, «уже есть заявка» по заявкам компании | — |
| Анкета (04–06) | подсказка реквизитов по ИНН, регистрация компании и черновика, отправка анкеты с файлами и ответами для оценки (шаг «Для оценки») | поля загружаются и автоматически сохраняются в БД через `GET/PUT /applications/{id}/draft`; отсутствующие значения показываются пустыми |
| Страница заявки после отправки | статус сбора и итог оценки credit-engine; вопросы банка с ответом и файлами; выбор предложения, скачивание демо-договора и подписание кодом через backend (`OFFERED → SIGNING → COMPLETED`); документы, отчёты ЭП и история | КЭП при подписании договора — у старых демо-заявок |
| Старые демо-заявки (07–15) | новые заявки обслуживает data-collector, включая демо-подписание | старые примеры по общему контракту остаются на MSW |
| Рабочее место банка (16–18) | очередь со счётчиками, досье (19 систем, расхождения, скоринг и решение credit-engine, предложенные условия), взять в работу, решение (одобрить, запросить данные, отказать) | перезапроса источника нет: ручки в сервисе нет |
| Живые обновления | опрос data-collector раз в 2 с | WebSocket — только у моков |

Префикс data-collector — `/collector/api/v1`: dev-сервер и nginx срезают `/collector` и проксируют на `COLLECTOR_PROXY_TARGET` / `COLLECTOR_UPSTREAM`. По умолчанию (`VITE_COLLECTOR_MOCK=true`) его ответы тоже отдаёт MSW — по swagger сервиса.

Анкета читает все заполненные поля из backend. Старые значения из localStorage не заменяют отсутствующие в БД. Файлы до отправки хранятся в IndexedDB, их список — в localStorage; токены маркетплейсов и ОФД — только в sessionStorage. Сохранение проверяет версию черновика и показывает ошибку, если другая вкладка уже изменила данные.

Остального бэкенда пока нет: запросы к `/api/v1` перехватывает [MSW](https://mswjs.io) (`src/mocks`), ответы — по контракту `../api/openapi.yaml`.
`VITE_API_MOCK=false` отключает демо-экраны, их запросы к `/api/v1` и WebSocket. Профиль, компании, заявки, каталог и рабочее место банка продолжают работать через data-collector. Ссылки на старые демо-заявки показывают «Экран в разработке». Для локального запуска с живым сервисом скопируйте `.env.example` в `.env` и поставьте оба флага `VITE_API_MOCK=false` и `VITE_COLLECTOR_MOCK=false`; адрес сервиса задаётся через `COLLECTOR_PROXY_TARGET`.

После отправки заявка в моке сама идёт по конвейеру FSM (`src/mocks/workflow.ts`): рассмотрение → вопросы банка (если подал не директор) или ручное рассмотрение (ИП Смирнов) → предложения. Каждый шаг занимает 2,5 с; ускорить можно ключом `credit-cabinet:mock-pipeline-ms` в `localStorage`. Изменения статуса приходят событиями через WebSocket `/api/v1/ws` (`docs/websocket.md`), MSW мокает его в браузере, а фронт по событию перечитывает REST (`src/api/live.ts`).

Изменения на моках (черновики, привязанные компании, документы) хранятся в `localStorage` браузера под ключом `credit-cabinet:mock-db:v10` и переживают перезагрузку. Чтобы вернуть исходные данные, удалите этот ключ в DevTools.

Версия Node — в `.nvmrc` (`nvm use`), зависимости закреплены точно (`.npmrc`: `save-exact`).

## Docker

Образ собирается в два этапа: Node собирает статику, nginx её раздаёт и проксирует `/api` (включая WebSocket) на `API_UPSTREAM`.

```bash
make front                         # из корня репозитория: собрать и поднять только фронт
# или вместе со всеми сервисами
make up
```

Фронт откроется на http://localhost:3000. Настройки — в корневом `.env`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `FRONTEND_PORT` | `3000` | порт на хосте |
| `FRONTEND_API_MOCK` | `true` | `true` — включены демо-экраны MSW; `false` — они отключены вместе с запросами к `/api/v1` и WebSocket. Значение вшивается при сборке; `make up` и `make front` пересобирают образ сами |
| `FRONTEND_COLLECTOR_MOCK` | `true` | `true` — ответы data-collector отдаёт MSW; `false` — запросы идут в живой сервис |
| `FRONTEND_COLLECTOR_UPSTREAM` | `http://data-collector:8081` | адрес data-collector в сети compose |
| `FRONTEND_API_UPSTREAM` | `http://api:8080` | адрес API в сети compose: схема, хост и порт **без пути** |

nginx стартует и без поднятого API: имя upstream резолвится при каждом запросе через DNS Docker (`NGINX_RESOLVER=127.0.0.11`; вне Docker поменяйте).
Заголовки безопасности лежат в `nginx/snippets/security-headers.conf` и подключаются в каждый `location`.

Моки работают только в secure context (`localhost` или https): Service Worker на `http://<ip>` браузер не запустит, и приложение пойдёт в настоящий API.
После переключения с моков на API на том же адресе старый worker можно снять в DevTools → Application → Service Workers → Unregister.

## E2E-тесты

Против живого data-collector тесты гонять в один поток (`--workers=1`): у них общая база, а черновик у пользователя по компании один. Тесты анкеты входят под заведёнными представителями компаний сценариев (Ковалёв, Литвинова, Смирнова): у них роль в компании задана заранее, поэтому прогоны не зависят от того, что накопилось в базе.

Тесты поднимают свой dev-сервер на порту 5179 и всегда на моках MSW (`VITE_API_MOCK=true`, `VITE_COLLECTOR_MOCK=true`); против живого стенда — `E2E_BASE_URL`. С живым data-collector добавьте `E2E_COLLECTOR_LIVE=1`: тесты на сбои и данные, которые есть только в моках, пропустятся.

Режим с обоими выключенными моками проверяется отдельно: `npx playwright test --config playwright.no-mocks.config.ts`. Тесты перехватывают ответы data-collector на границе сети и проверяют отсутствие запросов к `/api/v1`, WebSocket и запуска MSW.

[Playwright](https://playwright.dev), тесты лежат в `e2e/`:

| Файл | Что проверяет |
|---|---|
| `login.spec.ts` | список тестовых пользователей, вкладки ролей, выбор стрелками, вход, сессия после перезагрузки |
| `dashboard.spec.ts` | задачи «Ждут вашего действия», фильтр заявок, статусы по FSM, карточка компании, выход, нет вложенных интерактивных элементов |
| `auth.spec.ts` | гарды по ролям (гость, клиент, андеррайтер), ошибки `/me`: 500 без петли редиректов, 401 со сбросом токена |
| `backoffice.spec.ts` | рабочее место банка на API data-collector: заявка сценария B уходит в очередь; очередь (счётчики, фильтры, «Мои заявки», «Взять в работу»), досье (почему на ручном, источники, скоринг, чужая заявка без действий), решение (одобрить / запросить данные / отказать — клиент видит итог), 412 и 409 (только на моках), Esc, доступ клиента. С `E2E_COLLECTOR_LIVE=1` — против живого стека |
| `responsive.spec.ts` | телефон 375 px: ключевые страницы без горизонтальной прокрутки, шапка в экране, у этапов заявки подписан только текущий |
| `products.spec.ts` | каталог data-collector по задаче, «уже есть заявка» (тест сам подаёт заявку сценария B), пересчёт платежа, стрелки в radiogroup, сумма вне диапазона в форме и 422 расчёта |
| `application.spec.ts` | страница заявки: живое обновление статуса (страница и главная), параметры и история, отзыв (с рассмотрения и из уточнения), ответы на вопросы банка (выручка, МЧД + откреплённая подпись, подстановка распознанного, 422 по одному ответу), выбор предложения (410), отказ с удерживающим предложением (412) |
| `documents.spec.ts` | отказ банка с причинами и датой повторной заявки (и 404 «решения ещё нет»); вкладка «Документы»: таблица (распознавание, подпись, кто загрузил), отчёт о подписи и «не хватает подписей», .sig к загруженному документу, удаление с подтверждением (вместе с подписью), загрузка и удаление по статусу, ошибка скачивания |
| `signing.spec.ts` | подписание директором кодом (демо-код, попытки, после трёх неверных — назад к предложениям) и КЭП (.sig к договору), «ждём директора» с напоминанием, кредит выдан, скачивание документов |
| `wizard.spec.ts` | анкета на API data-collector (его моки): регистрация (сценарии A и D, ИНН вне подсказок, ликвидация, 422 у поля), проверки шагов (заёмщик, БИК, VIN, кадастровый номер, две подписи к документу), черновик и файлы после перезагрузки, отправка сценария A с файлом и `.sig` (что пришло в data-collector), МЧД для бухгалтера, ссылка на незаполненный шаг, 422 по шагам; повторный вход без дубля черновика, серверная ошибка пропадает после правки, токены только в sessionStorage и удаляются после отправки, двойной клик — одна отправка, кавычки в имени файла, согласие руководителя снимается вместе с ним. Против живого сервиса: `VITE_COLLECTOR_MOCK=false npx vite --port 5175` и `E2E_COLLECTOR_LIVE=1 E2E_BASE_URL=http://localhost:5175 npx playwright test e2e/wizard.spec.ts --workers=1` |
| `collector-status.spec.ts` | заявка data-collector после отправки: статус сам доходит до «данные собраны» (название и ОГРН из ЕГРЮЛ), итог сбора по 19 системам с причинами пропуска, документы и подпись, главная («Мои заявки» с заявкой и черновиком), черновик по ссылке статуса уходит в анкету, 404, сбор не удался (FAILED) — честный статус и опрос останавливается; вкладки «Документы» (скачивание, отчёт у `.sig`) и «История»; черновик коллеги не виден и не отправляется (403); итог оценки — предложение, отказ с причинами, ответы на вопросы банка (только на моках). Остальное проходит и против живого сервиса |

```bash
npx playwright install chromium   # один раз: браузер для тестов
npm run test:e2e                  # сам поднимет dev-сервер на моках
npm run test:e2e:ui               # интерактивный режим
E2E_BASE_URL=http://localhost:3000 npm run test:e2e   # против контейнера (make front)
```

Тесты опираются на синтетические данные из `src/mocks/data.ts`: если меняете моки, поправьте ожидания.

Ответы с ошибкой мок отдаёт по флагу в `localStorage` — так тесты проверяют сбои, не трогая обработчики. Пример: `credit-cabinet:mock-fail` = `[{"method":"PATCH","path":"/applications/","status":500,"times":1}]`. Необязательные поля: `code` (код Problem) и `field` (поле в `errors`). Хелперы для тестов — `setMockFailures` и `clearMockFailures` в `e2e/helpers.ts`.

## Структура

| Папка | Что внутри |
|---|---|
| `src/api` | `schema.d.ts` (генерируется из OpenAPI), клиент `openapi-fetch`, хуки TanStack Query, сессия мок-логина |
| `src/mocks` | сиды (`data.ts`), изменяемое хранилище в `localStorage` (`store.ts`), MSW-обработчики |
| `src/app` | роутинг, гард `RequireAuth` (роль + 401), хуки сессии `useAuth` |
| `src/pages` | страницы; каждый БЭМ-блок — свой `.tsx` + `.css` (например `LoginPage/components/PersonaCard`). Анкета — `WizardPage`: шаги в `steps/`, автосохранение в `useDraft.ts` (PATCH merge-patch + If-Match, очередь запросов, повтор при 412) |
| `src/shared` | общие компоненты (шапка, логотип, сумма+срок со слайдерами, платёж, карточка формы) и утилиты (форматирование, словари, merge-patch, Idempotency-Key) |
