# mock-api

Эмулятор внешних систем для локальной разработки и демо. Отдельный Go-модуль (gin), с остальными модулями общается только по HTTP.

Каждая система — своя папка (Go-пакет) с моками внутри, у каждой свой префикс пути:

| Папка | Префикс | Что эмулирует |
|---|---|---|
| [CoreBanking/](CoreBanking/) | `/core-banking/v1` | АБС банка: профиль клиента, обороты, транзакции, наши кредиты, картотека и блокировки |
| [FNS/](FNS/) | `/fns` | ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес», ГИР БО, блокировки счетов |
| [BKI/](BKI/) | `/bki/v1` | бюро кредитных историй (ответ «как НБКИ»), по компании и по собственнику |
| [Compliance/](Compliance/) | `/compliance/v1` | ЗСК ЦБ, перечни Росфинмониторинга, санкционные списки |
| [FSSP/](FSSP/) | `/fssp/v1` | исполнительные производства |
| [KAD/](KAD/) | `/kad/v1` | арбитражные дела |
| [Fedresurs/](Fedresurs/) | `/fedresurs/v1` | Федресурс / ЕФРСБ: банкротство, лизинг, ликвидация |
| [Bank/](Bank/) | `/bank/v1` | старый мок внутренних систем банка, его пока вызывает `data-collector` (см. ниже) |

Контракты, поля и смысл значений описаны в [docs/mock-apis.md](../docs/mock-apis.md).

## Данные

Ответы лежат в `<Система>/seed/<inn>.json` и встроены в бинарник. Чтобы поменять ответ, правим JSON и пересобираем. Чтобы добавить компанию, кладём `seed/<inn>.json` в нужные системы. Битый seed даёт panic при старте.

Тестовые сценарии согласованы между системами: имена, ОГРН, номера договоров и суммы совпадают.

| Сценарий | ИНН | Директор (ИНН) | Ожидаемый исход |
|---|---|---|---|
| A. Здоровый, ООО «СЕВЕРНЫЙ ВЕТЕР» | `7799000012` | Ковалёв И. С. (`779900010139`) | `OFFERED` |
| B. Перегружен долгами, ООО «СТРОЙРЕСУРС» | `7799000020` | Орлов Д. П. (`779900020136`) | `OFFERED`, но меньше сумма или дольше срок |
| C. Стоп-фактор, ООО «АЛЬТАИР» | `7799000037` | Белов А. Н. (`779900030147`) | `REJECTED` |
| D. ИП, мало данных, Смирнова А. В. | `779900010202` | она же | `WAITING_FOR_INFO` |
| E. Спорный, ООО «ТЕХНО-СЕРВИС» | `7799000044` | Зайцева О. М. (`779900040158`) | `MANUAL_REVIEW` |

Чтобы проверить стоп по санкциям, в `Compliance/seed/lists.json` есть субъекты, не связанные со сценариями: ФЛ «Громов Виктор Андреевич» 1979-03-02 и ЮЛ ООО «ТРАНЗИТ-ИНВЕСТ» с ИНН `7799000099`.

Транзакции Core Banking — ключевые операции, 10–20 в месяц: налоги, ФОТ, кредиты в других банках, лизинг, займы учредителя, инкассо. Помесячные обороты (`/turnover`) лежат отдельно и с суммой этих транзакций не сходятся.

«Сегодня» для моков зафиксировано: `2026-10-22` (`mockkit.AsOf`). От этой даты считаются срок согласия БКИ и `checked_at` в ответах по неизвестным ИНН.

## Общие правила

- Неверный ИНН (не 10 и не 12 цифр) → `400 INVALID_INN`.
- Неизвестный ИНН: карточка → `404 NOT_FOUND`; поиск или список → `200` с пустым результатом.
- Ошибка — `{"error": {"code": "...", "message": "..."}}`.
- `X-Request-Id` возвращается эхом.
- `X-Mock-Fault` имитирует отказ источника:
  - `500` → `INTERNAL_ERROR`;
  - `503` → `SERVICE_UNAVAILABLE` с `Retry-After: 5`;
  - `timeout` → ответ висит `MOCK_FAULT_TIMEOUT` (по умолчанию `30s`), потом `504`;
  - `captcha` → `403 CAPTCHA_REQUIRED`, у ФНС — `200 {"captchaRequired": true}`, как у реального egrul.

  На `/bank/v1` этот заголовок не действует.

Общий код (seed, ошибки, сбои, пагинация) — в [internal/mockkit](internal/mockkit/), помощники для тестов — в [internal/mocktest](internal/mocktest/).

## Bank

Старый мок. На любой ИНН из 10 или 12 цифр отдаётся один и тот же ответ (ООО «Ромашка»), на другой — `400`. Его вызывает `data-collector` (`GET /api/v1/check-mock`). Когда сбор данных перейдёт на новые моки, `Bank` удалим.

| Эндпоинт | Мок | Что внутри |
|---|---|---|
| `GET /bank/v1/companies/{inn}/accounts` | `accounts.json` | счета, остатки, транзакции (формат Open Banking) |
| `GET /bank/v1/companies/{inn}/credits` | `credits.json` | кредиты, долг, просрочки |
| `GET /bank/v1/companies/{inn}/acquiring` | `acquiring.json` | терминалы, оборот по картам, СБП |
| `GET /bank/v1/companies/{inn}/salary-project` | `salary_project.json` | зарплатный проект: реестры, ФОТ |
| `GET /bank/v1/companies/{inn}/card-index` | `card_index.json` | картотека: неоплаченные требования, блокировки, аресты |

Для `data-collector` эти моки — единственный источник тестовых данных банка, копий у него нет. Его контрактный тест ходит в запущенный mock-api (`make test-integration` в корне после `make up`). Тест падает, если в моке появилось поле, которого нет в `data-collector/internal/domain/bank.go`.

## Запуск

```bash
go run ./cmd/mock-api       # HTTP_ADDR по умолчанию :8090, MOCK_FAULT_TIMEOUT — 30s
go test ./...               # в т.ч. сквозная сверка сценариев между системами
curl -s localhost:8090/core-banking/v1/clients/7799000012/transactions?size=5
curl -s -XPOST localhost:8090/fns/egrul/ -d query=7799000037
curl -s -XPOST localhost:8090/bki/v1/reports \
  -d '{"subject_type":"LEGAL","inn":"7799000037","consent":{"id":"CNS-1","valid_until":"2027-04-21"}}'
curl -s -H 'X-Mock-Fault: 503' 'localhost:8090/fssp/v1/proceedings?inn=7799000012'
```

В docker-compose поднимается вместе со всем стеком (`make up` в корне).
