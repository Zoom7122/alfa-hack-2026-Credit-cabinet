# Источники данных о заёмщике (модуль «Сбор данных»)

> Исходим из того, что модуль работает **от имени банка со всеми лицензиями и договорами**: с бюро кредитных историй, с платформой ЦБ «Знай своего клиента», с ФНС через СМЭВ, с Росфинмониторингом.
> Поэтому **банк может запросить всё, что ниже**. Вопрос только в том, что прототип реально запрашивает, а что подменяет моком: условия кейса запрещают платные API и доступ к системам Альфа-Банка.
> Живые эндпоинты проверены curl 21.10.2026.

---

## 1. Как читать таблицы

- **Таблица 2** — все источники, которые банк может опросить:
  - **«Как банк получает»**: реальный канал и правовое основание (договор, согласие клиента, СМЭВ, публичный сервис);
  - **«Зачем источник существует»**: почему эти данные вообще кто-то собирает;
  - **«Зачем нам»**: что из них берём для кредитного решения;
  - **«В прототипе»**: как делаем в нашей версии (режимы ниже).
- **Таблица 3** — те же данные, но в разрезе отдельных признаков. Признаки отсортированы по **ценности для решения о кредите** (5 — критично, 1 — слабый сигнал). Колонка «Источник» ссылается на номер строки таблицы 2.
- **Роль в решении**: **Стоп** — сам по себе ведёт к отказу или ручной проверке; **Скоринг** — признак балльной модели; **Лимит** — влияет на сумму и срок; **Верификация** — подтверждает анкету и полномочия.

**Режимы в прототипе:**

| Режим | Значит |
|---|---|
| **LIVE** | Реально запрашиваем бесплатный публичный источник, кэшируем по ИНН, при сбое переходим на мок |
| **LIVE\*** | Реально запросить можно, но нестабильно (капча, защита от ботов, тяжёлые архивы). По умолчанию мок, живой режим по флагу |
| **DUMP** | Реальные открытые данные: скачиваем дамп один раз и кладём в свою БД, во время демо внешних вызовов нет |
| **DOC** | Клиент загружает файл, парсим его по-настоящему (в демо файлы синтетические) |
| **MOCK** | Банк получает это по договору, платно или из внутренних систем, нам недоступно. Делаем симулятор **с тем же контрактом и смыслом**, данные синтетические |
