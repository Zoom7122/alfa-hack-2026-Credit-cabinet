# Моки внешних систем: что можно получить, как и зачем

Справочник для тех, кто пишет сбор данных и скоринг. Здесь по каждому моку:
- **что** он отдаёт;
- **как** это получить: запрос, параметры, заголовки;
- **зачем** эти данные решению по заявке;
- что лежит в тестовых сценариях A–E.

Точные контракты (все поля и форматы) — в [mock-apis.md](mock-apis.md) и [mock-apis-wave-2-3.md](mock-apis-wave-2-3.md). Код и seed-данные — в [mock-api/](../mock-api/).

Адрес мока локально: `http://localhost:8090` (`make up` в корне). Ниже в примерах он сокращён до `$MOCK`.

Опросить все моки разом по одной компании можно через data-collector: `POST /api/v1/questionnaires`. Сбор асинхронный: ответ `202` со ссылкой на задачу, состояние — `GET /api/v1/collections/{id}`. Сырые ответы ложатся в таблицу `raw_collections`, по колонке на мок. Тела запросов и ключи внутри колонок — в [data-collector/README.md](../data-collector/README.md).

## Как пользоваться

### Общие правила

| Что | Как устроено |
|---|---|
| Ключ поиска | почти везде ИНН: 10 цифр у юрлица, 12 у ИП и физлица. Неверный формат → `400 INVALID_INN` |
| Неизвестный ИНН | карточка (клиент АБС, ЗСК, устав) → `404 NOT_FOUND`; поиск или список → `200` с пустым результатом. «Ничего не найдено» — это ответ, а не сбой |
| Ошибка | `{"error": {"code": "...", "message": "..."}}` |
| Деньги, даты | рубли, число с 2 знаками; даты ISO `YYYY-MM-DD`. Исключения: ГИР БО в **тыс. руб.**, ЕГРЮЛ с датами `14.03.2021`, мультибанкинг с суммами строкой |
| «Сегодня» | зафиксировано: `2026-10-22`. От этой даты считаются сроки согласий, окна «за 12 мес.», просрочки |
| Трассировка | `X-Request-Id` возвращается эхом |
| Имитация сбоя | `X-Mock-Fault: 500 \| 503 \| timeout \| captcha`. Работает на всех моках, кроме старого `/bank/v1`. `timeout` висит `MOCK_FAULT_TIMEOUT` (30 с), потом `504` |
| Токены клиента | маркетплейсы — `X-Seller-Token`, ОФД — `X-OFD-Token`. Подходит любое значение, кроме пустого и начинающегося с `invalid`; иначе `401` |
| Асинхронные запросы | налоговая отчётность, Госуслуги, согласия мультибанкинга: сначала `POST`, потом `GET` по id. Мок сразу отвечает «готово». Запросы живут в памяти и пропадают при перезапуске |

## Деньги и долги в нашем банке

### 1. Core Banking (АБС) — `/core-banking/v1`

Внутренние данные о клиенте: счета, обороты, транзакции, наши кредиты, ограничения по счетам.

| Запрос | Что вернёт |
|---|---|
| `GET /clients/{inn}` | профиль: тип (ЮЛ/ИП), сегмент МСП, клиент с какой даты, счета, продукты (эквайринг, зарплатный проект и число сотрудников, корпоративные карты) |
| `GET /clients/{inn}/turnover?months=12` | по месяцам (новые первыми): поступления, списания, эквайринг, средний и минимальный остаток, дни с нулевым остатком, число операций. `months` от 1 до 12 |
| `GET /clients/{inn}/transactions?from=&to=&page=&size=` | операции: дата, сумма, направление, код операции, контрагент (ИНН, банк, счёт), назначение. `size` до 500 (по умолчанию 100), `total` — сколько всего после фильтра |
| `GET /clients/{inn}/loans` | наши кредиты: лимит, остаток, ставка, платёж, сроки, текущая и прошлая просрочка, реструктуризация |
| `GET /clients/{inn}/restrictions` | картотека неоплаченных требований, блокировки ФНС, аресты ФССП по нашим счетам |

Неизвестный ИНН → `404` на всех ручках: значит, клиент не наш.

**Зачем:**
- **Выручка и её стабильность** по фактическим поступлениям: база для лимита и для DSCR (хватит ли денежного потока на все платежи).
- **Дни с нулевым остатком** показывают, что денег не хватает.
- **Скрытые долги** находятся по назначениям платежей: «Погашение … по кредитному договору №…» в другие банки, «Лизинговый платеж…».
- Ещё по назначениям видны:
  - налоги (ЕНП) и ФОТ;
  - займы учредителя;
  - **переводы самому себе**: их нельзя считать выручкой;
  - **инкассо** (код `06`, принудительное списание);
  - снятие наличных и транзит.
- **Наши кредиты** дают нагрузку и дисциплину у нас. В БКИ они видны как АО «АЛЬФА-БАНК», дважды их считать нельзя.
- **Картотека, блокировка, арест** — стоп-фактор: компания не может платить.

**В сценариях:**
- A: около 4,4 млн/мес, 2 кредита у нас, 1 кредит и 2 лизинга в других местах по выписке.
- B: около 2 млн/мес, 3 кредита в других банках по выписке.
- C: оборот падает с 3,1 до 0,9 млн; картотека 412 870, блокировка ФНС, арест; просрочка у нас 64 дня.
- D: счёт открыт 20.08.2026, обороты за 2 месяца — только выплаты WB.
- E: около 3,4 млн/мес; снятие наличных растёт, есть транзитные операции; оплаты по госконтрактам.

## Регистрация, налоги, полномочия

### 2. ФНС: ЕГРЮЛ, «Прозрачный бизнес», ГИР БО, блокировки — `/fns`

Пути и поля повторяют реальные сервисы ФНС: один адаптер разбирает и мок, и живой ответ, переключение — смена base URL.

| Что | Как получить | Что вернёт |
|---|---|---|
| ЕГРЮЛ / ЕГРИП | 1) `POST /fns/egrul/` с формой `query=<ИНН>` → токен `t`; 2) `GET /fns/egrul/search-result/{t}` | название, ИНН, ОГРН, КПП, дата регистрации, руководитель, тип (`ul`/`fl`), дата прекращения `e` у ликвидированных. Неизвестный ИНН → `rows: []` |
| «Прозрачный бизнес» | 1) `POST /fns/pb/search-proc.json` с `query=<ИНН>` → `token`; 2) `POST /fns/pb/company-proc.json` с `method=get-request&token=…` → `id`; 3) то же с `method=get-response&token=…&id=…` | ОКВЭД, уставный капитал, адрес, статус и флаги: недостоверность, долг по налогам, не сдаёт отчётность, массовый адрес, сколько компаний у директора, категория МСП |
| ГИР БО | 1) `GET /fns/bo/advanced-search/organizations/search?query=<ИНН>` → `id`; 2) `GET /fns/bo/nbo/organizations/{id}/bfo/` | баланс и отчёт о финрезультатах за 3 года в **тыс. руб.**: активы, капитал, кредиты, кредиторка, выручка, прибыль, операционный денежный поток |
| Блокировки счетов | `POST /fns/bi/bi2-proc.json` с формой `inn`, `bik` | действующие решения ФНС о приостановлении операций по счетам в банке с этим БИК |

`X-Mock-Fault: captcha` у ФНС отвечает как настоящий egrul: `200 {"captchaRequired": true}`.

```bash
T=$(curl -s -XPOST $MOCK/fns/egrul/ -d query=7799000037 | jq -r .t)
curl -s $MOCK/fns/egrul/search-result/$T
```

**Зачем:**
- **Существует ли компания и сколько ей лет** (ЕГРЮЛ). Ликвидация — стоп.
- **Флаги ПБ:**
  - недостоверность, долг по налогам, несдача отчётности — стоп или сильный негатив;
  - массовый адрес и директор с 5+ компаниями — признаки фирмы-однодневки.
- **ГИР БО:**
  - сверка выручки с заявленной и с оборотами;
  - рентабельность;
  - долг к выручке;
  - отрицательный капитал.
- **Блокировка** по любому банку — стоп: компания не может платить.

**В сценариях:**
- C: в ПБ стоит налоговый долг, блокировка у нас (решение 12873), отрицательный капитал за 2025.
- B: высокая долговая нагрузка в балансе.
- D (ИП): ЕГРИП `k: fl`, в ГИР БО пусто — ИП не сдают бухотчётность.

### 3. ФНС: устав, реестр МСП, дисквалификация

| Запрос | Что вернёт |
|---|---|
| `GET /fns/puchdoc/v1/{inn}` | устав: ограничения полномочий директора, порог крупной сделки (25% активов → сумма), кто одобряет, участники и доли. У ИП устава нет → `404` |
| `GET /fns/rmsp/v1/{inn}` | реестр МСП: категория (`MICRO`/`SMALL`/`MEDIUM`), численность, господдержка (гарантии фондов, гранты). Кого нет в реестре → `in_registry: false` |
| `GET /fns/disqualified/v1?inn=<ИНН физлица>` | дисквалифицирован ли человек: период, суд, статья КоАП |

**Зачем:**
- **Крупная сделка.** Если кредит больше `threshold_amount`, в список документов добавляется одобрение участника или общего собрания.
- **Ограничение директора** (`LOAN_LIMIT`): на большую сумму директор сам договор не подпишет.
- **Категория МСП** — продукты и программы господдержки. Гарантия фонда снижает риск.
- **Дисквалифицированный директор** — стоп.

**В сценариях:**
- A: порог 5 357 500, единственный участник.
- B: два участника (60/40), одобряет общее собрание.
- E: директор не может без согласия участника брать кредит больше 3 млн.
- Реестр МСП: A — гарантия фонда на 1,5 млн. B и E — `SMALL`, остальные — `MICRO`.
- Лаптев дисквалифицирован, директора сценариев — нет.

### 4. Реестр МЧД — `/m4d/v1`

| Запрос | Что вернёт |
|---|---|
| `GET /m4d/v1/poa/{номер}` | доверенность: статус (`ACTIVE`/`EXPIRED`/`REVOKED`), срок, кто выдал и кто подписал, представитель, полномочия. Неизвестный номер → `404` |
| `GET /m4d/v1/poa?principal_inn=…&representative_inn=…` | все доверенности компании (на конкретного человека, если указан) |

**Зачем:** проверки подписи `SIGNER_AUTHORITY` и `POA_VALID` ([e-signature.md](e-signature.md)). Подписант не директор → нужна действующая МЧД с нужным полномочием. Например, `LOAN_APPLICATION_SUBMIT` разрешает подать заявку, а `LOAN_CONTRACT_SIGN` — подписать договор.

**В сценариях:** у A три МЧД:
- главбуха Литвиновой, действующая, но без права подписи договора;
- её же, истёкшая;
- уволенного менеджера, отозванная.

### 5. Налоговая отчётность по согласию — `/tax-reports/v1`

Банк с согласия клиента получает из ФНС декларации и сальдо ЕНС.

| Шаг | Запрос |
|---|---|
| 1 | `POST /tax-reports/v1/requests`, тело: `inn`, `consent` (`id`, `valid_until`, `scope`: `DECLARATIONS` и/или `ENS_BALANCE`), `documents` (`PROFIT`, `VAT`, `USN`, `NPD_INCOME`, `ENS_BALANCE`), `periods` (`"2025"`, `"2026"`…) → `202 {request_id}` |
| 2 | `GET /tax-reports/v1/requests/{request_id}` → режим налогообложения и его история, документы, `not_available` с причиной |

Ошибки:
- `403 CONSENT_REQUIRED` — нет согласия;
- `403 CONSENT_EXPIRED` — согласие истекло;
- `403 CONSENT_SCOPE` — в согласии нет нужного права;
- `404` — неизвестный ИНН.

Причины в `not_available`: `NOT_APPLICABLE` (не тот режим), `NOT_DUE` (срок не наступил), `NOT_SUBMITTED` (не сдана в срок — негатив).

```bash
curl -s -XPOST $MOCK/tax-reports/v1/requests -H 'Content-Type: application/json' -d '{
  "inn":"779900010202","documents":["NPD_INCOME","USN","ENS_BALANCE"],"periods":["2024","2025","2026"],
  "consent":{"id":"TAX-1","valid_until":"2027-04-21","scope":["DECLARATIONS","ENS_BALANCE"]}}'
```

**Зачем:**
- **Выручка из декларации** — независимая сверка с ГИР БО и оборотами. Расхождение больше 20% → `REVENUE_MISMATCH`.
- **Доход ИП и самозанятых** — главный документ о выручке там, где нет бухотчётности.
- **Долг на ЕНС** означает, что скоро будет инкассо или блокировка.

**В сценариях:**
- A: ОСН, прибыль за 2025 сходится с ГИР БО, ЕНС +12 400.
- C: долг на ЕНС 412 870 (= инкассо в картотеке).
- D: доход НПД 1,14 млн (2024), 2,31 млн (2025), 2,29 млн (2026 до перехода на ИП); декларации по УСН ещё нет (`NOT_DUE`).
- B и E: ОСН, норма; НДС за 3 квартал 2026 ещё не наступил.

## Кредитная история и риски

### 6. БКИ — `/bki/v1`

| Запрос | Что вернёт |
|---|---|
| `POST /bki/v1/reports`, `{"subject_type":"LEGAL","inn":…,"consent":{…}}` | отчёт по компании |
| `POST /bki/v1/reports`, `{"subject_type":"PERSON","person":{"inn":…} \| {ФИО, birth_date},"consent":{…}}` | отчёт по физлицу: директор, поручитель, ИП |

В отчёте:
- балл бюро и грейд;
- сводка: активные и закрытые кредиты, лимиты, долг, ежемесячный платёж, текущая просрочка, эпизоды 30+/60+/90+ за 24 мес., реструктуризации, запросы истории за 7/30/90 дней;
- каждый кредит с помесячной историей платежей;
- кто запрашивал историю.

Без согласия → `403 CONSENT_REQUIRED`, с истёкшим → `403 CONSENT_EXPIRED`. Истории нет → `200`, `has_history: false`.

**Зачем:**
- **Долги по всему рынку** — знаменатель DSCR. Кредиты Альфы из отчёта исключаем: они уже есть в Core Banking.
- **Платёжная дисциплина**: просрочки и реструктуризации.
- **«Кредитный голод»**: много запросов истории за 30 дней.
- **Собственник** проверяется отдельно: его просрочки и долги — риск бизнеса.
- Лизинга в БКИ нет, его берём из Федресурса и выписки.

**В сценариях:**
- A: балл 712, без просрочек.
- B: 618, 5 активных кредитов, 6 запросов за 30 дней.
- C: 438, просрочка 64 дня у нас и 35 в Банке Восток, заём МФК; у директора кредит в дефолте.
- D: у бизнеса истории нет, у физлица чистая.
- E: 640, был эпизод 30+.

### 7. Compliance — `/compliance/v1`

| Запрос | Что вернёт |
|---|---|
| `GET /compliance/v1/zsk/{inn}` | уровень риска платформы ЦБ «Знай своего клиента»: `LOW`/`MEDIUM`/`HIGH` и коды причин |

## Как это складывается в решение

| Что оцениваем | Откуда берём |
|---|---|
| Компания существует и работает | ЕГРЮЛ, ПБ (статус, флаги), реестр МСП |
| Выручка | обороты Core Banking + мультибанкинг (без переводов себе) + ГИР БО (2110) + декларации; для ИП — маркетплейсы, НПД, УСН; для розницы — ОФД |
| Будущая выручка | неоплаченная часть госконтрактов |
| Долговая нагрузка (DSCR) | наши кредиты + БКИ без дублей Альфы + лизинг (Федресурс, сумма из выписки) + долги, найденные по назначениям платежей + залогодержатели из реестра залогов |
| Платёжная дисциплина | история в БКИ, просрочки по нашим кредитам, долг ЕНС |
| Стоп-факторы | картотека и блокировки (АБС, ФНС), флаги ПБ, долг ЕНС, ФССП «нет имущества», банкротство (КАД, Федресурс), РНП, санкции, ЗСК `HIGH`, дисквалификация, недействительный паспорт |
| Ручная проверка | ЗСК `MEDIUM`, крупные нерешённые иски, госпроверки с нарушениями, негативные новости |
| Залог | реестр залогов (движимое), ЕГРН (недвижимость) |
| Собственник и поручитель | ЕГРЮЛ/ПБ → БКИ, ФССП, Федресурс, санкции, дисквалификация, Госуслуги по физлицу |
| Документы и подпись | устав (крупная сделка, ограничения директора), МЧД представителя |

## Что с чем сходится

Моки согласованы между собой, и сквозной тест (`go test ./...` в `mock-api/`) это проверяет. Эти связки удобно использовать как проверки в сборе данных:

- **Реквизиты:** название, ИНН и ОГРН одинаковы в АБС, ЕГРЮЛ, ПБ, ГИР БО и БКИ.
- **Наши кредиты:** кредиты из АБС видны в БКИ как АО «АЛЬФА-БАНК» с теми же суммами.
- **Кредиты в других банках:** ежемесячные платежи по ним есть в выписке.
- **Лизинг:** договоры из Федресурса оплачиваются в выписке по номеру договора.
- **C, стоп-факторы:**
  - номер блокировки в АБС = решению ФНС;
  - арест = производству ФССП;
  - дело о банкротстве в КАД = сообщению Федресурса;
  - долг ЕНС = инкассо в картотеке.
- **Выручка:** декларация по прибыли = ГИР БО (выручка, налог). Безнал по чекам ОФД = эквайринг (A).
- **D:**
  - выплаты WB на счёт = поступления в выписке;
  - продажи на площадках = доход НПД = доход в Госуслугах.
- **A, переводы себе:** «переводы собственных средств» из Альфы = поступления на счёт в Банке Горизонт.
- **Залоги:** залогодержатели и ипотека (B, C) — кредиторы в БКИ.
- **Госконтракты:** оплаты заказчиков есть в выписке (E, C). Контракт из РНП — расторгнутый контракт C.
- **Устав и реестр МСП:** активы в уставе = ГИР БО. Категория и численность в реестре МСП = АБС.
